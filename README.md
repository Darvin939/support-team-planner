# Support Team Planner

Веб-приложение для планирования и отслеживания задач команд поддержки. Позволяет распределять задачи между
пользователями, управлять статусами выполнения, фиксировать дни фриза и просматривать статистику. Доступ — по
логину и паролю, все изменения задач и назначений фиксируются в истории.

---

## Возможности

- **Команды** — создание, редактирование и удаление команд с привязкой разрешённых шаблонов блоков раскатки.
- **Блоки раскатки** — именованные этапы деплоя (например, ГФ, Б1). Названия хранятся в верхнем регистре.
- **Шаблоны блоков** — наборы блоков со сдвигом в днях от базовой даты назначения; команде разрешается один или
  несколько шаблонов, что определяет, по какому графику для неё работает автоназначение.
- **Пользователи** — добавление и редактирование пользователей с ФИО; отдельный флаг определяет, показывается ли
  пользователь в выпадающих списках исполнителя (`is_assignee`) — например, у служебной учётной записи
  администратора он выключен.
- **Задачи** — создание задач с ручным приоритетом (перетаскивание строк для изменения порядка внутри команды) и
  зависимостями между задачами (с проверкой на циклы).
- **Планирование** — назначение задач на даты, распределение по пользователям, указание блоков и комментариев.
  Автоназначение по графику блоков команды. Таблица автоматически прокручивается к текущему дню.
- **Статусы назначений** — новый → запланирован → успешно / откат.
- **Статусы задач** — новый → выполнено / отменено. Задачи в терминальных статусах (выполнено/отменено) недоступны
  для редактирования.
- **Поиск задач** — нечёткий поиск по названию/описанию с допуском на опечатки (посимвольное скользящее окно).
- **Дни фриза** — добавление отдельных дат, диапазонов или замена целиком за месяц через модальное окно.
- **Статистика** — таблицы активных работ (new/planned) за период и на сегодня со счётчиками по статусам.
- **Сохранение фильтров** — выбранная команда и период дат сохраняются в localStorage и синхронизируются между
  страницами планирования и статистики.
- **Вход в систему** — доступ ко всему приложению закрыт логином и паролем (обычная форма, без выбора пользователя
  из списка); любой пользователь может сменить собственные логин/пароль через модальное окно «Мой аккаунт».
- **Роли** — три уровня доступа (`user` < `editor` < `admin`), каждый следующий включает права предыдущего.
  Страница `/settings` целиком закрыта для `user`; управление пользователями (создание/изменение/удаление,
  включая пароли и роли) доступно только `admin`; смена статуса задачи требует `editor` и выше, а `user` может
  создавать/менять/удалять задачи и назначения только пока их статус остаётся `new`. Роль проверяется на каждый
  запрос из БД, а не из сессии, — смена роли применяется немедленно, без перелогина.
- **История изменений** — каждое создание, изменение поля или удаление задачи/назначения фиксируется с указанием
  автора (если он известен) и времени. Просматривается прямо в модальных окнах задачи и назначения — по кнопке
  «История», в раскрывающейся панели справа, с пагинацией. История задачи включает и изменения всех её назначений
  (в том числе уже удалённых).

## Быстрый старт

```bash
# 1. Установите Python-зависимости
pip install -r requirements.txt

# 2. Соберите фронтенд — обязательный шаг: без актуальной сборки в frontend/dist/
#    ни одна страница не откроется
cd frontend
npm install
npm run build
cd ..

# 3. (опционально, но рекомендуется) задайте секрет для подписи сессии
export SESSION_SECRET_KEY="что-нибудь-случайное-и-длинное"

# 4. Запустите приложение
python support_planner.py
```

При первом запуске автоматически создастся файл `database.db` с необходимыми таблицами. Если `SESSION_SECRET_KEY` не
задан, приложение всё равно запустится, используя встроенный небезопасный ключ по умолчанию (в лог выводится
предупреждение) — подходит для локальной разработки, но не для продакшена.

**Важно:** `requirements.txt` на данный момент не включает `itsdangerous`, хотя он нужен для входа в систему
(подпись cookie-сессии) и не гарантированно тянется транзитивно другими зависимостями. Установите его
дополнительно: `pip install itsdangerous`.

**HTTPS (опционально):** при запуске приложение пытается получить TLS-сертификат из HashiCorp Vault
(`ssl_context.py`, переменные окружения `VAULT_ADDR`, `VAULT_TENANT`, `VAULT_KV_PATH`, `ROLE_ID`, `SECRET_ID`,
опционально через `.env`). Если Vault недоступен или переменные не заданы, приложение автоматически запускается по
обычному HTTP — для локальной разработки ничего настраивать не нужно.

Откройте браузер: [http://localhost:5093](http://localhost:5093)

**Первый вход:** при инициализации БД автоматически создаётся пользователь **«Администратор»** (роль `admin`) с
логином **`admin`** и паролем **`q12345678`** — под ним можно сразу войти и затем сменить логин/пароль (через
модалку «Мой аккаунт») или создать остальных пользователей через `/settings`. Создание идемпотентно — при
последующих запусках повторный пользователь не появляется, и удалить эту учётную запись нельзя.

### Разработка фронтенда

Для разработки с горячей перезагрузкой запускайте Vite dev-сервер параллельно с бэкендом — он проксирует `/api`,
`/login` и `/logout` на `:5093`:

```bash
python support_planner.py      # бэкенд на :5093
cd frontend && npm run dev     # Vite dev-сервер (см. адрес в выводе команды)
```

Для продакшен-запуска (с проверкой, что процесс уже не запущен, и логированием) используются `check.sh` и `run.sh`:

```bash
./check.sh   # запускает run.sh в фоне через nohup, если процесс ещё не работает
```

## Аутентификация и роли

Вход — по логину и паролю (обычная форма, без выбора пользователя из списка и без публичного списка пользователей).
Всё приложение (страницы и `/api/*`) закрыто логином, кроме `/login`, `/logout` и `/react-assets/*` (сам бандл
React должен грузиться ещё до входа):

| Метод | Путь        | Описание                                                                                            |
|-------|-------------|-------------------------------------------------------------------------------------------------------|
| GET   | `/login`    | Страница входа (React SPA)                                                                            |
| POST  | `/login`    | Вход (форма: `login`, `password`); при успехе — cookie-сессия, ответ `{"success": true}`              |
| POST  | `/logout`   | Выход, очистка сессии                                                                                  |
| GET   | `/api/me`   | Текущий пользователь (ФИО) и его роль (для клиентской навигации)                                       |
| PUT   | `/api/me`   | Сменить собственные `login`/`password` (доступно любой роли, не трогает ФИО/роль — модалка «Мой аккаунт») |

Без активной сессии запросы к страницам редиректят на `/login`, а запросы к `/api/*` возвращают
`401 {"error": "Не авторизован"}`.

**Роли** (`users.role`, ранги `user` < `editor` < `admin`, каждый следующий включает права предыдущего;
роль читается из БД на каждый запрос, а не из сессии, — смена роли применяется без перелогина):

- Любая роль: чтение (`GET`) везде, плюс создание/изменение/удаление задач и назначений (`/api/task`,
  `/api/assignment`, ...) — но `user` только пока их статус остаётся `new`: как только назначение переведено в
  `planned`/`success`/`rollback` или задача — не в статусе `new`, редактирование и удаление доступны только
  `editor` и выше. Менять статус задачи (`PATCH /api/tasks/{id}/status`) `user` не может вовсе.
- `editor` и выше: страница `/settings` целиком, плюс мутации команд, дней фриза, блоков и шаблонов блоков
  (`/api/teams`, `/api/freeze-days`, `/api/blocks`, `/api/block-templates`), смена статуса задач, и полный доступ
  к редактированию/удалению задач и назначений вне зависимости от статуса.
- `admin`: то же, что `editor`, плюс управление пользователями — создание/изменение/удаление, включая пароли,
  роли и флаг `is_assignee` (`/api/users`). `GET /api/users` остаётся доступен всем ролям (нужен для выпадающих
  списков исполнителя в планировщике).

При нехватке прав `/api/*` отвечает `403 {"error": "Недостаточно прав"}`, а обычная страница редиректит на
`/planning`.

## API

Все эндпоинты доступны через `/api/` и возвращают JSON.

### Команды

| Метод  | Путь              | Описание                         |
|--------|-------------------|-----------------------------------|
| GET    | `/api/teams`      | Список команд с их шаблонами     |
| GET    | `/api/teams/{id}` | Команда с разрешёнными шаблонами |
| POST   | `/api/teams`      | Создать команду                  |
| PUT    | `/api/teams/{id}` | Обновить команду                 |
| DELETE | `/api/teams/{id}` | Удалить команду                  |

### Пользователи

| Метод  | Путь              | Описание                                                                                                    |
|--------|-------------------|----------------------------------------------------------------------------------------------------------------|
| GET    | `/api/users`      | Список пользователей (доступен всем ролям)                                                                     |
| POST   | `/api/users`      | Создать пользователя (тело: `login`, `password`, `role` — `user`/`editor`/`admin`, `is_assignee`), только `admin` |
| PUT    | `/api/users/{id}` | Обновить пользователя (`login`/`password` не указаны/пустые → не меняются), только `admin`                     |
| DELETE | `/api/users/{id}` | Удалить пользователя (кроме служебной учётной записи администратора по умолчанию), только `admin`              |

### Задачи

| Метод  | Путь                                | Описание                                                                                                 |
|--------|-------------------------------------|-------------------------------------------------------------------------------------------------------------|
| GET    | `/api/tasks/{team_id}`              | Задачи команды (`?search=&offset=&limit=&show_completed=`, дефолт 20/стр., нечёткий поиск)                 |
| POST   | `/api/task`                         | Создать / обновить задачу (тело может включать `dependency_ids`)                                            |
| DELETE | `/api/task/{id}`                    | Удалить задачу (мягкое удаление — `is_deleted = 1`, без физического DELETE)                                 |
| PATCH  | `/api/tasks/{id}/status`            | Обновить статус задачи (тело: `{"status": "..."}`), только `editor` и выше                                  |
| PATCH  | `/api/tasks/{team_id}/reorder`      | Переставить приоритет задач в пределах загруженной страницы (перетаскивание строк)                          |
| PATCH  | `/api/task/{id}/priority`           | Переместить задачу в начало/конец списка всей команды (контекстное меню)                                    |
| GET    | `/api/tasks/{team_id}/deps`         | Зависимости всех задач команды                                                                              |
| GET    | `/api/tasks/{team_id}/active-list`  | Плоский список активных задач команды (для выбора зависимостей)                                             |
| GET    | `/api/task/{id}/history`            | Объединённая история задачи и всех её назначений, включая удалённые (`?offset=&limit=`, дефолт 20/стр.)     |

### Назначения

| Метод  | Путь                           | Описание                                                                              |
|--------|--------------------------------|-----------------------------------------------------------------------------------------|
| GET    | `/api/assignments/{team_id}`   | Назначения команды (фильтр: `?start_date=&end_date=`)                                 |
| POST   | `/api/assignment`              | Создать / обновить назначение                                                          |
| DELETE | `/api/assignment/{id}`         | Удалить назначение (мягкое удаление — `is_deleted = 1`, без физического DELETE)        |
| GET    | `/api/assignment/{id}/history` | История изменений назначения, пока оно существует (`?offset=&limit=`, дефолт 20/стр.) |

### Блоки и шаблоны блоков

| Метод  | Путь                        | Описание                              |
|--------|-----------------------------|-----------------------------------------|
| GET    | `/api/blocks`               | Список всех блоков                    |
| POST   | `/api/blocks`               | Создать блок                          |
| DELETE | `/api/blocks/{id}`          | Удалить блок                          |
| GET    | `/api/block-templates`      | Список всех шаблонов блоков с блоками |
| POST   | `/api/block-templates`      | Создать шаблон блоков                 |
| PUT    | `/api/block-templates/{id}` | Обновить шаблон блоков                |
| DELETE | `/api/block-templates/{id}` | Удалить шаблон блоков                 |

### Дни фриза

| Метод  | Путь                                    | Описание                            |
|--------|-------------------------------------------|----------------------------------------|
| GET    | `/api/freeze-days`                      | Список дней фриза                   |
| POST   | `/api/freeze-days`                      | Добавить день или диапазон          |
| DELETE | `/api/freeze-days/{date}`               | Удалить день                        |
| PUT    | `/api/freeze-days/month`                | Заменить дни фриза за месяц целиком |
| DELETE | `/api/freeze-days/month/{year}/{month}` | Удалить все дни фриза за месяц      |

### Активные назначения (статистика)

| Метод | Путь                                | Описание                                                                                         |
|-------|-------------------------------------|-----------------------------------------------------------------------------------------------------|
| GET   | `/api/active-assignments/{team_id}` | Активные назначения (new/planned), `?start_date=&end_date=&team_ids=`, team_id=0 для всех команд |

## База данных

**Движок:** SQLite (файл `database.db`, автоматическое создание при первом запуске).

**Таблицы:**

- `teams` — команды
- `blocks` — блоки раскатки
- `block_templates` + `template_blocks` — шаблоны блоков и их состав (блок + сдвиг в днях)
- `team_templates` — связь команда ↔ разрешённые шаблоны
- `users` — пользователи (колонки `login` и `password_hash`, обе nullable и независимы от ФИО — без обеих
  пользователь не может войти в систему; `login` уникален; `role`, `NOT NULL DEFAULT 'user'` — см.
  «Аутентификация и роли»; `is_assignee`, `NOT NULL DEFAULT 1` — показывать ли пользователя в выпадающих списках
  исполнителя)
- `freeze_days` — дни фриза
- `tasks` — задачи (привязаны к команде; колонки `task_status`, `priority`, `is_deleted`)
- `task_dependencies` — зависимости между задачами (граф, проверяется на циклы при добавлении)
- `assignments` — назначения (связь задачи, даты и пользователя; уникальность по `task_id` + `date` среди
  неудалённых записей; колонка `is_deleted`)
- `task_history` / `assignment_history` — история изменений: одна запись на изменённое поле (плюс отдельная запись
  на создание/удаление), с автором (`changed_by_user_id`, может быть `NULL`) и временем

Задачи и назначения не удаляются физически — удаление помечает строку флагом `is_deleted = 1`, поэтому запись
истории всегда может сослаться на исходную строку через полноценный внешний ключ, даже после «удаления».

**Примечание:** `database.db` добавлен в `.gitignore` и не хранится в репозитории.

## Разработка

- Приложение запускается через Uvicorn на порту 5093.
- При удалении пользователя с активными назначениями они открепляются (`user_id` → `NULL`), но не удаляются; это
  изменение тоже попадает в историю назначения.
- Период в фильтрах ограничен 60 днями, даты — диапазоном 2000–2099.
- Поиск задач нечувствителен к опечаткам (до ~1 ошибки на 7 символов слова).
- Интерфейс выполнен на русском языке.
- Три роли (`user`/`editor`/`admin`) — см. раздел «Аутентификация и роли» выше.
- Автор изменения в истории (`changed_by_user_id`) берётся из cookie-сессии на момент запроса; если сессии нет
  (или запись сделана до появления логина), автор не указывается (`NULL`), а не подставляется как «неизвестно».
- Тесты в `tests/` сейчас не запускаются — актуальных исходников там нет (`python -m pytest tests/ -v` находит 0
  тестов).
