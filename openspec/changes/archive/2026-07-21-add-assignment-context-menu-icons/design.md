## Context

Контекстное меню назначения формируется в `usePlanningColumns.tsx` из `ASSIGNMENT_STATUS_OPTIONS`: текущий статус исключается, а остальные пункты получают только `key` и `label`. В контекстном меню работы иконки уже есть у статусов и графа, но отсутствуют у действий перемещения в начало и конец уровня критичности. Новый визуальный паттерн и зависимость не требуются.

## Goals / Non-Goals

**Goals:**

- дать каждому возможному статусу назначения устойчивую семантическую иконку;
- показывать иконку во всех доступных пунктах смены статуса;
- визуально различить перемещение работы в начало и конец уровня критичности;
- не менять существующую фильтрацию пунктов и обработчики мутаций.

**Non-Goals:**

- изменение набора или правил переходов статусов;
- добавление новых действий в меню;
- изменение backend/API или модели данных.

## Decisions

1. Использовать компоненты из `@ant-design/icons`: `PlusCircleOutlined` для `new`, `CalendarOutlined` для `planned`, `UndoOutlined` для `rollback`, `CheckCircleOutlined` для `success`, `CloseCircleOutlined` для `cancelled`. Эти образы различимы и соответствуют смыслу статусов.
2. Хранить соответствие статус → иконка в типизированном объекте рядом с `ASSIGNMENT_STATUS_OPTIONS`, а при построении `MenuProps['items']` задавать поле `icon`. Это централизует отображение и не вмешивается в существующий `onClick`.
3. Использовать `VerticalAlignTopOutlined` для «В начало уровня критичности» и `VerticalAlignBottomOutlined` для «В конец уровня критичности». Направление иконки непосредственно отражает результат действия и не требует отдельной карты из двух значений.
4. Проверить production UI через Python + Playwright: открыть контекстные меню редактируемого назначения и активной работы, затем убедиться, что пункты статуса и приоритета содержат иконки.

## Risks / Trade-offs

- [Некоторые иконки могут интерпретироваться неоднозначно без текста] → подписи статусов сохраняются, иконки используются только как дополнительный визуальный ориентир.
- [Новый статус может остаться без иконки при будущем расширении] → типизированная полная карта по `AssignmentStatus` даст ошибку TypeScript при рассогласовании union-типа.
