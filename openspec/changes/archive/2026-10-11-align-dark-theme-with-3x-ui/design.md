## Context

Тема централизована в `frontend/src/theme.ts`: Ant Design получает `darkTheme` через корневой `ConfigProvider`, а `AppShell` отдельно использует набор `chrome`. Большинство страниц и оверлеев уже используют производные токены через `theme.useToken()`, поэтому изменение источника должно распространиться без локальных CSS-переопределений. См. мотивацию в `proposal.md` и поведенческие границы в delta-спеках.

## Goals / Non-Goals

**Goals:**

- Согласовать уровни поверхностей `darkTheme` и тёмного `chrome` с обычным dark-режимом 3x-ui.
- Сохранить единый источник цветов для страниц, таблиц, карточек, модальных окон и dropdown.
- Зафиксировать значения токенов unit-тестами и проверить итоговый контраст production UI.

**Non-Goals:**

- Добавление третьего ultra-dark режима или нового элемента управления темой.
- Перенос всей системы тем 3x-ui либо изменение семантических цветов приложения.
- Изменение светлой темы, backend или API.

## Decisions

### 1. Заменить только нейтральные токены

В `darkTheme.token` меняются `colorBgBase`, `colorBgLayout`, `colorBgContainer` и `colorBgElevated`; значения `colorPrimary`, `colorSuccess`, `colorWarning`, `colorError` и `colorInfo` сохраняются. Это делает фон светлее без изменения визуального языка статусов и действий.

Альтернатива — полностью скопировать конфигурацию 3x-ui — отклонена, поскольку она изменила бы семантические цвета и потребовала повторной проверки всех статусных состояний.

### 2. Синхронизировать chrome с отдельным уровнем оболочки

`chrome.dark.bg` становится `#15161a`, как header/sidebar обычной тёмной темы 3x-ui. Цвет текста сохраняется, если визуальная проверка не выявит недостаточный контраст.

Альтернатива — оставить почти чёрный sidebar — отклонена: он сохранял бы ощущение ultra-dark и нарушал согласованность поверхностей.

### 3. Не менять модель состояния темы

`App.tsx` продолжает хранить бинарный `isDark` и ключ `theme`. Значение палитры меняется прозрачно для уже сохранённого выбора.

Альтернатива — перенять ключи `dark-mode` и `isUltraDarkThemeEnabled` — отклонена: ultra-dark не входит в scope, а миграция не даёт пользовательской пользы.

### 4. Проверять токены и итоговый интерфейс разными уровнями тестов

Vitest проверяет точные токены и сохранение семантических значений. Production Playwright проверяет login, planning, settings, модальные и всплывающие поверхности при реальной авторизации; визуальная проверка проводится на типичном desktop viewport и на узком viewport для responsive-регрессий.

## Risks / Trade-offs

- [Некоторые локальные смешивания через `color-mix` станут визуально светлее сильнее ожидаемого] → проверить таблицу планирования, статусные ячейки и карточки в production UI.
- [Светлый sidebar может снизить различимость навигации и контента] → проверить границу, выбранный пункт и hover; корректировать только chrome-токены, не возвращая ultra-dark фон.
- [Точные значения upstream могут в будущем измениться] → считать зафиксированные значения частью локального контракта, а не автоматически синхронизируемой зависимостью.

## Migration Plan

1. Обновить централизованные нейтральные токены и chrome.
2. Запустить unit/component-тесты и production-сборку.
3. Выполнить production Playwright-проверку с WAL-безопасным backup/restore БД.
4. При регрессии откатить только значения токенов; данные пользователей и localStorage миграции не требуют.
