## Why

Пользователь с ролью `user` сейчас может получить возможность изменить статус назначения через интерфейс или прямой API-запрос, хотя управление жизненным циклом назначений должно оставаться у редакторов и администраторов. Пользователю нужно оставить только создание назначения, причём его начальный статус должен всегда быть `new` («Новый»).

## What Changes

- Backend запрещает роли `user` менять статус существующего назначения независимо от используемого одиночного или массового маршрута.
- При создании назначения ролью `user` backend принимает только статус `new` и отклоняет запрос с любым другим статусом.
- Frontend скрывает или блокирует для роли `user` все элементы управления статусом назначения и при создании использует только статус «Новый».
- Ролевое поведение покрывается backend- и frontend-тестами, включая попытки обойти ограничение прямым API-запросом.

## Capabilities

### New Capabilities

- `assignment-status-role-policy`: Ролевая политика создания назначений и изменения их статуса для пользователя, редактора и администратора.

### Modified Capabilities

Нет.

## Impact

- Backend-маршруты сохранения одиночных и массовых назначений и централизованные проверки роли.
- Модальное окно назначения, контекстное меню статуса и связанные frontend mutations.
- Backend API-тесты и Vitest/React Testing Library тесты поведения интерфейса.
- Публичный формат API не меняется; ужесточается авторизация операций для роли `user`.
