## ADDED Requirements

### Requirement: Пользователь создаёт назначение только со статусом «Новый»
Система SHALL разрешать роли `user` создание назначения только с начальным статусом `new` и MUST отклонять попытку создать назначение с любым другим статусом.

#### Scenario: Создание нового назначения пользователем
- **WHEN** пользователь отправляет запрос на создание назначения со статусом `new`
- **THEN** система создаёт назначение со статусом `new`

#### Scenario: Создание назначения пользователем с повышенным статусом
- **WHEN** пользователь отправляет запрос на создание назначения со статусом, отличным от `new`
- **THEN** система отвечает HTTP 403 и не создаёт назначение

### Requirement: Пользователь не меняет статус существующего назначения
Система SHALL запрещать роли `user` менять статус любого существующего назначения через одиночные и массовые операции, независимо от текущего статуса назначения.

#### Scenario: Смена статуса нового назначения одиночным запросом
- **WHEN** пользователь пытается обновить существующее назначение со статусом `new`, передав другой статус
- **THEN** система отвечает HTTP 403 и сохраняет прежний статус назначения

#### Scenario: Смена статуса назначения массовым запросом
- **WHEN** массовая операция пользователя содержит изменение статуса хотя бы одного существующего назначения
- **THEN** система отклоняет всю операцию без частичного сохранения

#### Scenario: Обновление без смены статуса
- **WHEN** пользователь обновляет разрешённые поля существующего назначения и передаёт его неизменённый статус
- **THEN** система сохраняет разрешённые изменения, не меняя статус

### Requirement: Интерфейс пользователя не предлагает смену статуса назначения
Frontend SHALL не показывать роли `user` интерактивные элементы смены статуса существующего назначения и SHALL использовать `new` при создании назначения.

#### Scenario: Контекстное меню назначения для пользователя
- **WHEN** пользователь взаимодействует с назначением в таблице планирования
- **THEN** интерфейс не показывает действие или варианты смены статуса назначения

#### Scenario: Создание назначения в модальном окне
- **WHEN** пользователь открывает форму создания назначения
- **THEN** статус установлен в `new` и пользователь не может выбрать другой статус

### Requirement: Повышенные роли сохраняют управление статусом
Система SHALL сохранять возможность ролей `editor` и `admin` создавать назначения с допустимыми статусами и менять статус существующих назначений по действующим правилам.

#### Scenario: Редактор меняет статус назначения
- **WHEN** редактор отправляет допустимое изменение статуса существующего назначения
- **THEN** система сохраняет новый статус
