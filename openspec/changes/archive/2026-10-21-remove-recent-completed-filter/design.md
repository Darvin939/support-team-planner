## Context

Основной список планировщика сейчас поддерживает флаг `include_recent_completed`: при его включении API и DAO добавляют к активным задачам терминальные задачи, завершённые в последние 30 дней. Флаг управляет чекбоксом в карточке фильтров и входит в состояние запроса и пагинации. Полный архив уже имеет отдельные API и интерфейс с поиском, диапазоном дат и пагинацией.

## Goals / Non-Goals

**Goals:**

- Удалить переключатель, фильтр статуса работы и все ветви состояния, запросов, API и DAO, существующие для включения недавних завершённых задач в основной список.
- Оставить основной список активных задач и сохранить отдельный архив для терминальных задач.
- Сохранить согласованность поиска, пагинации и `total` для оставшейся выборки.

**Non-Goals:**

- Менять критерии активных и терминальных статусов или статусы, доступные при редактировании работы.
- Менять фильтры, поиск и пагинацию архива или формат его API.
- Менять доступ к одной задаче или её историю.

## Decisions

- Удалить `include_recent_completed` из endpoint основного списка и соответствующие аргументы DAO; SQL основного списка всегда исключает `done` и `cancelled`. Это убирает неподдерживаемую продуктом ветку и не оставляет API скрытого переключателя.
- Удалить checkbox и прокинутые через страницу планирования `showCompleted` state/props. Удалить этот флаг из ключа запроса и зависимостей сброса пагинации; прочие параметры запроса остаются без изменений.
- Удалить фильтр `task_status` из планировщика: единственный нетерминальный статус задачи — `new`, поэтому после удаления терминальных работ такой фильтр не может сузить основной список. Другие фильтры планировщика сохраняются.
- Сохранить архивный endpoint и UI без изменений. Пользователи, которым нужны терминальные задачи, переходят через действие «Архив».
- Обновить delta-спецификацию: устаревшие требования о переключателе и недавней выборке удаляются; новые требования фиксируют активный основной список и доступ к терминальной истории через архив.

## Risks / Trade-offs

- Клиенты, передававшие `include_recent_completed`, потеряют возможность расширять основной список; это намеренное удаление режима. Архив остаётся штатным способом просмотра терминальных задач.
- Счётчик `total` и пагинация должны продолжать использовать тот же активный фильтр, что и элементы страницы; покрыть это существующими backend-тестами.

## Migration Plan

Изменить frontend и backend в одном релизе: сначала убрать режим из API/DAO и затем обновить все вызовы frontend. Для отката можно восстановить прежний код без миграции данных: схема БД не меняется.
