## Context

При запросе графа с `task_id` backend возвращает связную компоненту работы. Для работы без зависимостей ответ содержит одну ноду и ноль рёбер. Frontend сейчас считает граф пустым только при нулевом количестве нод.

## Goals / Non-Goals

**Goals:**

- Показывать `Empty` для графа конкретной работы без рёбер.
- Сохранить прежнее поведение общего графа команды.

**Non-Goals:**

- Изменение API или DAO.
- Скрытие графа конкретной работы, если в её компоненте есть хотя бы одно ребро.

## Decisions

1. Вычислять пустое состояние по сырым данным API: `nodes.length === 0 || (taskId !== undefined && edges.length === 0)`. Это не зависит от асинхронной синхронизации xyflow state.
2. Для изолированной работы показывать тот же компонент `Empty`, но с описанием «У работы нет зависимостей». Для пустого общего графа сохранить «В команде нет задач».

## Risks / Trade-offs

- [API может вернуть больше одной ноды без рёбер из-за дефекта] → Критерий пустоты основан на самом отсутствии связей, что соответствует смыслу представления.
