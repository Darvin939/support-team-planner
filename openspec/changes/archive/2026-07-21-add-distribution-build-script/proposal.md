## Why

Сейчас приложение можно запускать только из рабочего дерева проекта после ручной сборки frontend. Нужен воспроизводимый способ подготовить отдельный переносимый каталог с минимальным набором файлов для установки и запуска приложения.

## What Changes

- Добавить Linux shell-скрипт, который собирает production-frontend и формирует дистрибутив в отдельном каталоге.
- Включать в дистрибутив Python-исходники и зависимости, `frontend/dist`, а также frontend-файл данных, который backend читает во время запуска.
- Исключать из дистрибутива исходники разработки, локальную БД, секреты, логи, кэши и OpenSpec-артефакты.
- Останавливать сборку с понятной ошибкой при неуспешной frontend-сборке или отсутствии обязательных файлов.
- Документировать команду сборки, структуру результата и способ запуска приложения из дистрибутива.

## Capabilities

### New Capabilities

- `application-distribution-build`: Воспроизводимое формирование автономного каталога приложения из Python runtime-файлов и production frontend-артефактов.

### Modified Capabilities

Нет.

## Impact

Изменение затронет новый скрипт сборки в корне репозитория, `.gitignore` для каталога результата и `README.md`. API и пользовательское поведение приложения не меняются; новые Python/npm-зависимости не требуются.
