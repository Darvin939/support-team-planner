## ADDED Requirements

### Requirement: Ролевая политика объявляется на маршруте

Каждый защищённый backend endpoint MUST явно объявлять минимальную допустимую роль через зависимость FastAPI на endpoint или его `APIRouter`; решение о доступе MUST NOT выводиться из строкового сопоставления URL-пути.

#### Scenario: Endpoint требует роль редактора
- **WHEN** endpoint с явно объявленной минимальной ролью `editor` вызывает пользователь с ролью `user`
- **THEN** backend отклоняет запрос с действующим статусом и форматом ошибки недостаточных прав

#### Scenario: Endpoint допускает более высокую роль
- **WHEN** endpoint с минимальной ролью `editor` вызывает пользователь с ролью `admin`
- **THEN** ролевая зависимость разрешает выполнение endpoint

#### Scenario: Добавлен новый защищённый endpoint
- **WHEN** разработчик добавляет защищённый endpoint без явной зависимости аутентификации или роли
- **THEN** автоматическая проверка матрицы маршрутов выявляет отсутствие декларации доступа

### Requirement: Аутентификация, роль и доступ к ресурсу разделены

Backend SHALL отдельно определять текущего session user, проверять глобальную роль и проверять доступ пользователя к конкретной команде, задаче или назначению. Ролевая зависимость MUST предоставлять handler проверенного текущего пользователя без повторного чтения идентичности из необработанной session.

#### Scenario: Аутентифицированный запрос
- **WHEN** защищённый endpoint вызывается с действующей пользовательской сессией
- **THEN** зависимость текущего пользователя предоставляет handler идентификатор и роль существующего пользователя

#### Scenario: Пользователь удалён после создания сессии
- **WHEN** session содержит идентификатор пользователя, которого больше нет в базе
- **THEN** backend очищает недействительную сессию и отвечает по действующему контракту неавторизованного запроса

#### Scenario: Роль разрешена, но команда недоступна
- **WHEN** пользователь с достаточной глобальной ролью обращается к сущности недоступной ему команды
- **THEN** ресурсная проверка отклоняет запрос по действующим правилам командного доступа

### Requirement: Публичность маршрутов задаётся явно

Маршруты входа, выхода и статических ресурсов SHALL оставаться явно публичными, а все остальные API и document endpoints SHALL требовать действительную сессию, если для них явно не установлена публичная политика.

#### Scenario: Публичный маршрут входа
- **WHEN** неавторизованный клиент открывает `/login`
- **THEN** backend возвращает страницу входа без требования session user

#### Scenario: Защищённый API endpoint
- **WHEN** неавторизованный клиент вызывает защищённый `/api/*` endpoint
- **THEN** backend возвращает действующий ответ `401` в JSON-формате

#### Scenario: Защищённый document endpoint
- **WHEN** неавторизованный клиент открывает защищённую SPA-страницу
- **THEN** backend выполняет действующее перенаправление на `/login`
