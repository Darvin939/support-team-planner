## Context

`api_models.py` уже содержит `Literal`-алиасы для критичности, роли, статусов работы, назначения и ПСИ. При этом routes повторно проверяют некоторые из этих значений локальными tuple/set, а терминальные статусы работы многократно прописаны в Python и SQL runtime-коде. В результате существует несколько независимых мест, которые требуется менять синхронно.

## Goals / Non-Goals

**Goals:**

- Сделать Pydantic единственным слоем проверки допустимости входных enum-значений.
- Типизировать пока строковую позицию приоритета.
- Централизовать семантическую группу терминальных статусов для runtime-кода.
- Сохранить текущие бизнес-ограничения, переходы и API-формат ошибок.

**Non-Goals:**

- Изменение наборов допустимых значений.
- Замена `Literal` на Python `Enum`.
- Изменение исторических migration steps.
- Перенос карты переходов из `taskTransitions.json`.

## Decisions

1. `api_models.py` остаётся источником допустимых входных значений. Routes не повторяют membership-проверки полей, уже типизированных `Literal`: неизвестные значения отсекаются FastAPI/Pydantic до входа в handler.
2. Для `TaskPriorityIn.position` вводится `PriorityPosition = Literal['start', 'end']`. Это устраняет последнюю ручную проверку простого enum в task routes.
3. Семантика «терминальный статус» относится к бизнес-правилам, а не к API-схеме. Общий неизменяемый набор и helper размещаются в `task_rules.py`; Python-код использует helper/набор вместо локальных tuple.
4. Runtime SQL использует централизованный helper для построения параметризованного `IN`/`NOT IN`, если запрос уже собирается динамически. Статические сложные запросы оцениваются отдельно: централизация не должна приводить к интерполяции значений в SQL.
5. `db/sqlite_migration_steps.py` сохраняет исторические литералы. Миграции должны оставаться воспроизводимыми независимо от будущего изменения runtime-домена.
6. Контрактные AST-тесты проверяют отсутствие известных дублирующих route-констант и согласованность `TaskStatus`, terminal set и `taskTransitions.json`.

## Risks / Trade-offs

- [Удаление route-проверки меняет старый HTTP 400 на стандартный 422] → это уже фактический контракт строгих Pydantic-моделей; обновить тесты на единый формат 422.
- [Обобщение SQL усложнит простые запросы] → менять только runtime-запросы, где helper остаётся читаемым; не создавать небезопасную строковую интерполяцию.
- [Циклический импорт между models и rules] → `task_rules.py` может импортировать тип/метаданные из `api_models.py`, но `api_models.py` не должен импортировать business rules.

## Migration Plan

Миграция данных и схемы не требуется. Изменение разворачивается как обычное обновление backend; rollback выполняется возвратом к предыдущему коду.
