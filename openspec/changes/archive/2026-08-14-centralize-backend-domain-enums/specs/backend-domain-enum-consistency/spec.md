## ADDED Requirements

### Requirement: Pydantic является единственным валидатором входных enum-значений
Backend SHALL объявлять допустимые значения простых входных перечислений в Pydantic-моделях и MUST NOT повторять те же membership-наборы в route handlers.

#### Scenario: Допустимое enum-значение
- **WHEN** запрос содержит значение из соответствующего `Literal`-типа
- **THEN** Pydantic принимает значение и route применяет только последующие бизнес-правила

#### Scenario: Неизвестное enum-значение
- **WHEN** запрос содержит неизвестную критичность, роль, статус или позицию приоритета
- **THEN** запрос отклоняется до выполнения handler стандартной ошибкой валидации HTTP 422

### Requirement: Терминальные статусы имеют единый runtime-источник
Backend SHALL определять семантическую группу терминальных статусов работы `done` и `cancelled` в одном runtime-источнике и SHALL переиспользовать её в Python business/DAO-коде и безопасно параметризуемых runtime SQL-проверках.

#### Scenario: Python проверяет терминальность
- **WHEN** business rule или DAO определяет, завершена ли работа
- **THEN** проверка использует общий terminal helper или общий неизменяемый набор, а не локальный tuple строк

#### Scenario: Runtime SQL фильтрует терминальные работы
- **WHEN** runtime-запрос строит фильтр по терминальным статусам
- **THEN** значения берутся из общего runtime-источника и передаются параметрами без интерполяции пользовательских данных

#### Scenario: Историческая миграция воспроизводима
- **WHEN** выполняется ранее выпущенный migration step
- **THEN** его исторические статусные литералы остаются неизменными и не зависят от текущего runtime-набора

### Requirement: Переходы статусов остаются независимым контрактом
Система MUST продолжать читать допустимые переходы статусов из `taskTransitions.json`; terminal set SHALL описывать только группировку статусов и MUST NOT становиться второй картой переходов.

#### Scenario: Проверка перехода работы
- **WHEN** API получает запрос на изменение статуса работы
- **THEN** допустимость перехода определяется `taskTransitions.json`, а terminal helper используется только для поведения завершённых работ
