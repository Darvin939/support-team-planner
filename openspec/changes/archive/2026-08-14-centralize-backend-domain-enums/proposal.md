## Why

Backend уже объявляет доменные перечисления в `api_models.py`, но отдельные routes и runtime-правила повторно прописывают те же наборы строк вручную. Такие дубли могут расходиться с Pydantic-контрактом и менять формат ошибки в зависимости от слоя проверки.

## What Changes

- Удалить ручные route-проверки критичности и роли, уже гарантированные типами Pydantic.
- Ввести тип для позиции изменения приоритета (`start`/`end`) и удалить соответствующую ручную проверку.
- Определить единый runtime-набор терминальных статусов работы и использовать его в Python business/DAO-коде.
- Для SQL runtime-запросов формировать проверку терминальных статусов из общего источника безопасными placeholders там, где это не ухудшает читаемость и параметры запроса.
- Не переписывать исторические migration steps: их литералы фиксируют состояние миграции на момент выпуска.
- Сохранить `taskTransitions.json` единственным источником допустимых переходов между статусами.
- Добавить контрактные тесты, предотвращающие возврат дублирующей route-валидации и рассинхронизацию runtime-наборов.

## Capabilities

### New Capabilities

- `backend-domain-enum-consistency`: единые источники доменных перечислений для API-валидации и runtime business rules без дублирующих route-наборов.

### Modified Capabilities

Нет.

## Impact

Изменение затрагивает `api_models.py`, routes задач и пользователей, runtime task rules/DAO/SQL helpers и backend-тесты. Публичные допустимые значения API, схема SQLite, данные и migration registry не изменяются; неизвестные enum-значения продолжают отклоняться стандартной Pydantic-валидацией с HTTP 422.
