## Why

При выборе периода на странице статистики пользователь не видит, на какие даты приходится больше активных работ. Счётчики в календаре помогут быстрее выбирать и оценивать периоды без перебора дат в таблице.

## What Changes

- В каждой видимой ячейке даты RangePicker на странице статистики появится компактный счётчик активных работ, включая видимые даты соседних месяцев; нулевые счётчики не отображаются.
- Значения от `1` до `9` отображаются точно, а значения `10` и больше — как `9+`, без раскрытия точного значения.
- Счётчики учитывают те же правила активности, права доступа и выбранные команды, что и таблица статистики.
- Backend возвращает агрегированные по датам количества без загрузки всех назначений.
- Данные загружаются для всех реально видимых ячеек обеих панелей и обновляются при перелистывании календаря или изменении фильтра команд.
- Загрузка счётчиков не блокирует выбор дат; ошибка показывается одним общим уведомлением, а календарь остаётся доступным.
- Стандартное позиционирование, поведение, стили состояний и доступность RangePicker сохраняются.

## Capabilities

### New Capabilities

- `statistics-calendar-work-counts`: отображение агрегированного количества активных работ по датам в календаре статистики.

### Modified Capabilities

Нет.

## Impact

- Frontend: `StatisticsPage`, hook/API-типы статистики, query keys, `cellRender` Ant Design RangePicker и адаптивные стили.
- Backend: API статистики, модель ответа и SQL-агрегация `COUNT(*) GROUP BY date` с существующими фильтрами активных назначений.
- Тесты: backend API/DAO, Vitest + React Testing Library для логики и взаимодействий календаря, production Playwright для визуальной и интеграционной проверки.
- Новых зависимостей, изменений схемы БД и breaking changes нет.
