## Context

Проверка `get_task_completion_suggestion` сейчас собирает все неудалённые назначения работы, пересекающиеся с блоками сохранённого шаблона, и требует статус `success` у каждого из них. Из-за этого историческое `cancelled`-назначение блокирует предложение, хотя в остальной доменной логике отменённые назначения не считаются активными.

## Goals / Non-Goals

**Goals:**

- Исключить `cancelled`-назначения из расчёта покрытия и блокирующих статусов.
- Сохранить требование полного покрытия каждого блока шаблона успешными назначениями.
- Закрепить регрессионный сценарий с отменённым дублем блока и успешным актуальным назначением.

**Non-Goals:**

- Не менять модель статусов назначений.
- Не менять триггер проверки: предложение по-прежнему формируется после перехода назначения в `success`.
- Не менять вид модалки предложения и переходы статуса работы.

## Decisions

1. **Фильтровать `cancelled` до расчёта покрытия.** Отменённое назначение не добавляет блоки в `covered_blocks` и не добавляет статус в `relevant_statuses`. Это согласует проверку с уже закреплённым правилом «отмена не считается активным назначением».
2. **Не переходить к правилу «хотя бы один `success` на блок» для всех статусов.** Активный `new`, `planned` или `rollback`, пересекающийся с шаблоном, по-прежнему блокирует готовность. Иначе можно было бы завершить работу при незаконченном активном дубле.
3. **Оставить API-контракт без изменений и унифицировать frontend-обработку.** `AssignmentModal` получает callback `onTaskCompletionSuggested` от `PlanningPage`. При успешном сохранении форма сначала передаёт предложение, если оно есть, затем закрывается. Контекстное меню и форма тем самым обновляют одно и то же состояние `completionSuggestion`.
4. **Проверить поведение на двух уровнях.** Backend-тест покроет матрицу статусов и отменённый дубль; frontend-тест покроет передачу предложения из `AssignmentModal` и поведение самой модалки. Полный Playwright-сценарий проверит путь через форму на production-сборке и копии текущей БД.

## Risks / Trade-offs

- [Отменённое назначение было единственным покрытием блока] → после исключения `cancelled` блок останется непокрытым, и предложение не появится.
- [Скрытая регрессия для активных неуспешных дублей] → явно сохранить и протестировать блокирующее поведение `new`, `planned` и `rollback`.
- [Различие production-данных и тестовых fixtures] → повторить Playwright-проверку на текущей БД с backup/restore через SQLite API.
