## Why

На prod-like БД отменённое историческое назначение блока блокирует предложение завершить работу, даже если тот же блок и все остальные блоки шаблона уже покрыты успешными назначениями. Дополнительно форма назначения теряет корректное `task_completion_suggestion` из API-ответа, поэтому модалка не появляется при завершении через форму.

## What Changes

- Проверка готовности работы игнорирует назначения со статусом `cancelled`.
- Каждый блок непустого сохранённого шаблона по-прежнему должен быть покрыт хотя бы одним успешным назначением.
- Неотменённое назначение блока шаблона со статусом, отличным от `success`, продолжает блокировать предложение завершить работу.
- Backend-и frontend-поведение покрывается регрессионными тестами.
- Форма редактирования назначения передаёт полученное `task_completion_suggestion` странице планирования для показа той же модалки, что и при смене статуса из контекстного меню.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `template-driven-task-completion`: уточняется, что отменённые назначения исключаются из проверки полного успешного покрытия шаблона.

## Impact

- Backend DAO: логика `get_task_completion_suggestion`.
- API одиночного сохранения назначения: формирование `task_completion_suggestion`.
- Frontend: `AssignmentModal` и его интеграция с `PlanningPage`.
- Backend-тесты матрицы готовности и frontend component/integration-тест показа модалки.
- Миграции БД и изменения публичной схемы API не требуются.
