## Why

Ссылка на инструкцию сейчас хранится вместе с произвольным описанием, из-за чего её нельзя однозначно валидировать, показать и изменять как самостоятельный атрибут работы. Нужно выделить для неё отдельное необязательное поле, не ограничивая при этом ссылки в тексте описания.

## What Changes

- Добавить к работе необязательный nullable-атрибут `instruction_url` для абсолютной HTTP(S)-ссылки на инструкцию.
- Добавить nullable-колонку в SQLite-схему и идемпотентную миграцию для существующих БД.
- Принимать, валидировать, сохранять и возвращать `instruction_url` в существующих API работ, включая историю изменений.
- Добавить на вкладку `Основное` модалки отдельное поле `Ссылка на инструкцию`, а в read-only-режиме показывать её как кликабельную безопасную ссылку.
- Показывать в колонке `Работа` планировщика компактную ссылку `Инструкция ↗`, если `instruction_url` заполнен.
- Сохранить текущее поле `Описание` и преобразование HTTP(S)-адресов внутри его текста в кликабельные ссылки.
- Не переносить автоматически существующие ссылки из `description`: поле инструкции у таких работ останется пустым до явного редактирования.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `task-management`: Модель и API работы получают отдельную валидируемую ссылку на инструкцию.
- `task-modal-layout`: Frontend получает отдельное поле, кликабельное read-only-представление и компактную ссылку в планировщике, не изменяя поддержку ссылок в описании.

## Impact

- SQLite-схема, миграции и тесты миграций.
- DAO работ, история изменений, Pydantic-модели и task API.
- Frontend-типы, payload сохранения, `TaskModal`, колонка работы планировщика, форматирование истории и component-тесты.
- Production frontend build и Playwright-проверка редактируемого/read-only представления.
