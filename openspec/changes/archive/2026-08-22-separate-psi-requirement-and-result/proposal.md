## Why

Сейчас модальное окно работы смешивает два разных решения: требуется ли ПСИ и пройдено ли оно. Из-за трёхсоставного списка пользователь может случайно изменить результат ПСИ при обычном редактировании работы, поэтому настройку требования и фиксацию результата нужно разделить.

## What Changes

- В форме работы заменить выбор из трёх состояний ПСИ на чекбокс «ПСИ требуется».
- При редактировании сохранять уже пройденное ПСИ, пока пользователь не отключил требование явно; включение требования для работы без ПСИ переводит её в `required`.
- Полностью блокировать изменение чекбокса ПСИ в модальном окне, если у работы есть назначения, чтобы требование нельзя было снять без предварительного удаления назначений.
- Добавить в контекстное меню активной работы действие с подтверждением для переходов `required` → `passed` и `passed` → `required`.
- Сохранить текущие подписи, цвета и расположение маркеров ПСИ в планировщике без визуальных изменений.
- Сохранить серверные ограничения: терминальную работу изменять нельзя, а менять требование ПСИ в любую сторону при существующих назначениях нельзя.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `task-psi-planning-gate`: разделить управление требованием ПСИ в форме работы и изменение результата ПСИ через подтверждаемое действие контекстного меню.

## Impact

- Frontend: форма работы, блокировка чекбокса по признаку назначений, контекстное меню строки планировщика, мутации и инвалидация данных, component-тесты.
- Backend: отдельная узкая операция изменения результата ПСИ либо эквивалентное расширение существующего API с проверками доступа, статуса работы и двусторонним запретом изменения требования при назначениях; аудит изменения работы.
- Схема БД и набор значений `psi_status` не меняются.
