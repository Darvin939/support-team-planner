## Context

Сейчас `TaskModal` загружает таймлайн только для работ со статусом `done` или `cancelled`; секция расположена в основной вкладке. Архив раскрывает строку и отображает тот же `AssignmentTimeline`. Хук `useTaskAssignmentTimeline` использует защищённый endpoint, который уже возвращает все неудалённые назначения, независимо от статуса, и не зависит от периода планировщика.

## Goals / Non-Goals

**Goals:**
- Показывать таймлайн назначений в основной вкладке карточки любой существующей работы.
- Сохранить просмотр полного набора назначений всех статусов в раскрытой строке архива.
- Загружать таймлайн карточки при открытии и наличии ID работы, переиспользуя query cache и общий компонент.

**Non-Goals:**
- Изменять endpoint, схему данных, фильтрацию по статусам или период планировщика.
- Менять формат группировки назначений по дате: текущие правила данных исключают несколько статусов у назначений одной даты.
- Менять существующую панель истории изменений.

## Decisions

- Убрать зависимость `enabled` запроса таймлайна карточки от терминального статуса. Включать запрос, когда карточка открыта и у работы есть ID. Это сохраняет ленивую загрузку и позволяет показывать историю у активной работы.
- Оставить секцию таймлайна в основной вкладке рядом с текущими полями карточки. Компонент уже показывает состояния загрузки, ошибки и пустой истории.
- Оставить архив на существующем API и `AssignmentTimeline`: endpoint выбирает все строки `is_deleted = 0` и не фильтрует `status`, а архив уже загружает данные при раскрытии строки.
- Не добавлять фильтр по датам планировщика: диапазон таймлайна строится от самой ранней до самой поздней даты назначений работы.

## Risks / Trade-offs

- [Активные карточки будут дополнительно запрашивать историю назначений при открытии] → запрос выполнять только для открытой карточки существующей работы; React Query кэширует результат по ID работы.
- [Большой разрыв между датами назначений создаёт широкий таймлайн] → сохраняется существующая горизонтальная прокрутка с ограничением ширины.

## Migration Plan

Изменение только frontend; миграция БД и обратная совместимость API не требуются. Откат заключается в возврате условия загрузки только для терминальных работ.
