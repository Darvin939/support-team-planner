## MODIFIED Requirements

### Requirement: Любая роль меняет ПСИ только у активной работы
Система SHALL разрешать ролям `user`, `editor` и `admin` менять требование и результат ПСИ доступной активной работы и SHALL запрещать это для завершённой, отменённой или удалённой работы. Требование ПСИ SHALL управляться чекбоксом в форме работы при отсутствии неудалённых назначений со статусом, отличным от `new`, а результат обязательного ПСИ SHALL изменяться отдельным действием контекстного меню с подтверждением.

#### Scenario: Пользователь отмечает прохождение ПСИ
- **WHEN** роль `user` подтверждает в контекстном меню перевод доступной активной работы из `required` в `passed`
- **THEN** система сохраняет состояние и автора изменения в истории работы

#### Scenario: Пользователь возвращает требование после прохождения
- **WHEN** роль `user` подтверждает в контекстном меню перевод доступной активной работы из `passed` в `required` и у работы нет назначений со статусом, отличным от `new`
- **THEN** система сохраняет состояние `required` и автора изменения в истории работы

#### Scenario: Отмена подтверждения результата
- **WHEN** пользователь отменяет подтверждение перехода между `required` и `passed`
- **THEN** система не изменяет состояние ПСИ

#### Scenario: Изменение терминальной работы
- **WHEN** любая роль пытается изменить ПСИ работы в статусе `done` или `cancelled`
- **THEN** backend отклоняет изменение по общей терминальной блокировке

#### Scenario: Изменение требования при черновом плане
- **WHEN** работа имеет только назначения `new` и клиент переводит её из `not_required` в `required` либо из `required`/`passed` в `not_required`
- **THEN** backend разрешает изменение при соблюдении остальных штатных проверок

#### Scenario: Изменение требования при активном плане
- **WHEN** работа имеет хотя бы одно назначение со статусом, отличным от `new`, и клиент переводит её из `not_required` в `required` либо из `required`/`passed` в `not_required`
- **THEN** backend отклоняет изменение с сообщением о необходимости удалить или вернуть в черновик активные назначения

### Requirement: Обязательные непройденные ПСИ допускают только черновое планирование
Система SHALL при `psi_status = required` разрешать создание, автоназначение, редактирование, перенос и удаление назначений `new`, но SHALL запрещать создание назначения другого статуса, смену статуса `new` и перепланирование существующего назначения другого статуса. Все операции MUST дополнительно соблюдать штатные ролевые и терминальные ограничения.

#### Scenario: Создание нового назначения до прохождения ПСИ
- **WHEN** клиент создаёт назначение со статусом `new` для активной работы с `psi_status = required`
- **THEN** backend сохраняет назначение при соблюдении остальных штатных проверок

#### Scenario: Создание активного назначения до прохождения ПСИ
- **WHEN** клиент создаёт назначение со статусом, отличным от `new`, для работы с `psi_status = required`
- **THEN** backend отклоняет запрос и не создаёт назначение

#### Scenario: Массовое автоназначение до прохождения ПСИ
- **WHEN** bulk upsert содержит только назначения `new` работ с `psi_status = required`
- **THEN** система атомарно сохраняет их при соблюдении остальных штатных проверок

#### Scenario: Недопустимый элемент массового сохранения
- **WHEN** bulk upsert содержит хотя бы одно назначение другого статуса для работы с `psi_status = required`
- **THEN** вся операция отклоняется без частичного сохранения

#### Scenario: Перенос нового назначения
- **WHEN** клиент переносит существующее назначение `new` работы с `psi_status = required`
- **THEN** backend разрешает перенос при соблюдении остальных штатных проверок

#### Scenario: Перенос активного назначения
- **WHEN** клиент переносит существующее назначение со статусом, отличным от `new`, работы с `psi_status = required`
- **THEN** backend отклоняет перенос

#### Scenario: Смена статуса нового назначения
- **WHEN** любая роль пытается перевести назначение `new` работы с `psi_status = required` в другой статус
- **THEN** backend отклоняет изменение

#### Scenario: Неплановые поля legacy-назначения
- **WHEN** существующему назначению другого статуса работы с `psi_status = required` изменяют только комментарий или трудозатраты
- **THEN** backend разрешает изменение при соблюдении ролевых правил

#### Scenario: ПСИ не требуется или пройдено
- **WHEN** работа имеет `not_required` или `passed`
- **THEN** операции планирования продолжают проходить остальные штатные проверки

### Requirement: Состояние ПСИ заметно и управляемо в планировании
Frontend SHALL показывать в модальном окне работы чекбокс требования ПСИ, SHALL блокировать этот чекбокс при наличии назначения со статусом, отличным от `new`, SHALL предоставлять переходы результата `required` ↔ `passed` в контекстном меню строки работы с подтверждением и SHALL отображать состояние компактным маркером в строке метаданных работы рядом с сегментом согласно установленным подписям.

#### Scenario: Новая работа без требования ПСИ
- **WHEN** пользователь создаёт работу с выключенным чекбоксом «Требуется ПСИ»
- **THEN** frontend отправляет `not_required`

#### Scenario: Включение требования ПСИ
- **WHEN** пользователь сохраняет работу, ранее имевшую `not_required`, с включённым чекбоксом «Требуется ПСИ»
- **THEN** frontend отправляет `required`

#### Scenario: Редактирование работы с пройденным ПСИ
- **WHEN** пользователь сохраняет работу со статусом `passed`, не выключая чекбокс «Требуется ПСИ»
- **THEN** frontend сохраняет `passed`, не возвращая работу в `required`

#### Scenario: Отключение требования после прохождения
- **WHEN** работа со статусом `passed` не имеет назначений со статусом, отличным от `new`, пользователь выключает чекбокс и сохраняет форму
- **THEN** frontend отправляет `not_required`

#### Scenario: Работа только с черновыми назначениями
- **WHEN** пользователь открывает форму работы, у которой есть только неудалённые назначения `new`
- **THEN** checkbox «Требуется ПСИ» отображает текущее значение и доступен для изменения

#### Scenario: Работа с активным назначением
- **WHEN** пользователь открывает форму работы, у которой есть хотя бы одно неудалённое назначение со статусом, отличным от `new`
- **THEN** checkbox «Требуется ПСИ» отображает текущее значение, но недоступен для изменения

#### Scenario: Требуется ПСИ
- **WHEN** работа имеет `psi_status = required`
- **THEN** строка работы показывает оранжевый маркер `Требуется ПСИ`, позволяет календарные действия только для назначений `new`, фиксирует их статус и предлагает отметить ПСИ пройденным

#### Scenario: Пояснение чернового режима
- **WHEN** пользователь открывает форму назначения работы с `psi_status = required`
- **THEN** frontend показывает сообщение «До прохождения ПСИ доступны только назначения в статусе „Новый“»

#### Scenario: ПСИ пройдено
- **WHEN** работа имеет `psi_status = passed`
- **THEN** рядом с сегментом строка работы показывает текущий зелёный маркер `ПСИ ✓`, а контекстное меню предлагает вернуть состояние `required`

#### Scenario: ПСИ не требуется
- **WHEN** работа имеет `psi_status = not_required`
- **THEN** строка работы не показывает бейдж ПСИ, разрешает планирование и не показывает действие изменения результата ПСИ
