## ADDED Requirements

### Requirement: Все списки используют единую модель пагинации
Frontend SHALL хранить состояние пагинации всех серверных и клиентских списков через общий hook в виде `page` и `pageSize`, SHALL вычислять из них `offset` для API и SHALL не хранить `offset` как независимый UI-state.

#### Scenario: Серверный список
- **WHEN** пользователь переходит на страницу `page` с размером `pageSize`
- **THEN** запрос отправляет `offset = (page - 1) * pageSize` и `limit = pageSize`

#### Scenario: Клиентский справочник
- **WHEN** локальный массив отображается постранично
- **THEN** он использует тот же общий hook и срез по вычисленному `offset`, а не отдельный `useState(page)`

#### Scenario: Сброс после изменения выборки
- **WHEN** команда, поиск, фильтр, период, контекст Drawer или идентификатор сущности изменяет состав выборки
- **THEN** соответствующая пагинация сбрасывается на первую страницу

### Requirement: Все экраны используют единый компонент пагинации
Frontend SHALL отображать постраничную навигацию только через общий проектный компонент, основанный на Ant Design `Pagination`; прямое использование Ant Design `Pagination`, `OffsetPagination` и локальные обёртки пагинации вне общего компонента SHALL отсутствовать.

#### Scenario: Основной список
- **WHEN** пагинация показана под основной таблицей
- **THEN** общий компонент использует стандартный вид, единые отступы и выравнивание и при явном разрешении показывает выбор размера страницы

#### Scenario: Компактная область
- **WHEN** пагинация показана в узкой панели, Drawer или небольшом справочнике
- **THEN** тот же общий компонент использует явно запрошенный компактный режим и фиксированный размер страницы

#### Scenario: Одна страница данных
- **WHEN** `total <= pageSize`
- **THEN** общий компонент не отображает навигацию

### Requirement: Возможности управления соответствуют источнику данных
Общий компонент SHALL показывать переключатель размера страницы только при явном `allowPageSizeChange`, а обработчик SHALL обновлять `pageSize`, сбрасывать `page` и использовать новый размер в следующем запросе.

#### Scenario: Изменяемый размер
- **WHEN** пользователь выбирает новый размер в основном списке с `allowPageSizeChange`
- **THEN** hook сохраняет новый `pageSize`, устанавливает `page = 1`, а запрос использует новый `limit`

#### Scenario: Фиксированный размер
- **WHEN** Drawer, история, архив или локальный справочник использует фиксированный размер
- **THEN** переключатель размера не отображается и пользователь не может выбрать неподдерживаемое значение

### Requirement: Текущая страница остаётся допустимой
Frontend SHALL нормализовать текущую страницу после получения нового `total`, если удаление, восстановление или изменение выборки уменьшило число страниц.

#### Scenario: Последняя страница исчезла
- **WHEN** `page` больше `max(1, ceil(total / pageSize))`
- **THEN** общий механизм устанавливает последнюю допустимую страницу и загружает её данные

#### Scenario: Данные ещё не загружены
- **WHEN** актуальный `total` отсутствует во время загрузки
- **THEN** механизм не сбрасывает текущую страницу на основании временного значения
