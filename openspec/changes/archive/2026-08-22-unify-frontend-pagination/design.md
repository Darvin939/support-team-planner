## Context

Backend последовательно использует `offset/limit`, но frontend исторически накопил четыре UI-подхода: `PagePagination`, `OffsetPagination`, прямой Ant Design `Pagination` и локальные компоненты с ручным `useState`. `usePaginationState` уже вычисляет `page`, `pageSize` и `offset`, однако используется не везде, а некоторые потребители преобразуют offset обратно в page.

Критичный дефект есть в Drawer уведомлений: `PagePagination` всегда показывает size changer, хотя Drawer хранит только `page`, игнорирует новый `pageSize` и продолжает запрашивать фиксированные 20 элементов.

## Goals / Non-Goals

**Goals:**

- Один hook состояния и один компонент отображения для всех пагинируемых списков.
- Единая граница: UI использует `page/pageSize`, API получает `offset/limit`.
- Явно различать фиксированный и изменяемый размер без ложных элементов управления.
- Нормализовать страницу после уменьшения `total`.
- Сохранить компактное представление там, где стандартная пагинация физически не помещается.

**Non-Goals:**

- Изменение backend API на page-based контракт.
- Сохранение выбранного `pageSize` в localStorage или профиле пользователя.
- Добавление cursor-based pagination.
- Изменение размеров страниц, кроме устранения фактических несоответствий состояния и запроса.

## Decisions

### Единственный компонент `AppPagination`

`PagePagination` переименовывается в `AppPagination` и получает контракт:

- `current`, `pageSize`, `total?: number`, `onChange`;
- `allowPageSizeChange` — по умолчанию `false`;
- `compact` — по умолчанию `false`.

Компонент централизует `PAGE_SIZE_OPTIONS`, скрытие для одной страницы, отступы и выравнивание. `compact` меняет только допустимое представление Ant Design (`simple`/`small`), но не модель состояния. Альтернатива с отдельными full/offset-компонентами сохраняет текущее дублирование.

### `usePaginationState` является единственным state owner

Все потребители, включая Drawer и клиентские справочники, используют `usePaginationState`. Hook продолжает возвращать `page`, `pageSize`, вычисленный `offset`, `reset` и `onChange`. `setOffset` удаляется после миграции: он поддерживает offset-модель внутри UI и провоцирует обратные преобразования.

Запросы получают `pagination.offset` и `pagination.pageSize`; отображение получает `pagination.page`, `pagination.pageSize` и `pagination.onChange`.

### Нормализация выполняется общим компонентом при известном total

`AppPagination` принимает `total?: number`. В effect он сравнивает `current` с последней допустимой страницей и вызывает `onChange(lastPage, pageSize)`, если текущая страница больше неё. При `total === undefined` нормализация не выполняется, поэтому загрузочное состояние не сбрасывает страницу.

Альтернатива с effect на каждой странице дублирует правила. Передача `total` непосредственно в hook создаёт циклическую организацию: hook нужен до запроса, а total появляется после запроса.

### Основные и фиксированные списки задают возможности явно

- Планировщик, журнал, пользователи, команды и статистика: `allowPageSizeChange = true`.
- История, архив, уведомления и справочники блоков: фиксированный размер и `allowPageSizeChange = false`.
- Узкие HistoryPanel и Drawer используют `compact`; остальные используют стандартный вид.

В статистике остаются две независимые текущие страницы, но общий `pageSize`: смена размера синхронно вызывает `setPageSize` обоих hook и сбрасывает обе страницы. `StatsSection` получает page-based параметры без offset-конвертации.

## Risks / Trade-offs

- [Автоматическая нормализация вызывает дополнительный запрос после удаления последней записи] → это ожидаемый второй запрос последней допустимой страницы; не использовать оптимистический фиктивный total.
- [Компактный режим визуально отличается от стандартного] → различается плотность, но структура, состояние, скрытие и возможности остаются едиными и управляются одним компонентом.
- [Массовая миграция затрагивает много экранов] → выполнять по группам и покрыть общий компонент/hook тестами плюс целевые component-тесты основных, Drawer и локальных списков.
- [Передан `total = 0` во время загрузки] → тип `total?: number`; потребители передают `undefined`, пока ответ отсутствует.

## Migration Plan

1. Расширить общий компонент и тесты, сохранив временную совместимость текущего `PagePagination`.
2. Мигрировать серверные основные списки и статистику.
3. Мигрировать фиксированные модальные/Drawer-списки и локальные справочники.
4. Удалить старые компоненты, ручные преобразования и прямые импорты Ant Pagination.
5. Выполнить production-сборку и визуально проверить стандартный и компактный варианты на desktop/mobile.

Откат возвращает прежние обёртки; backend и данные не затрагиваются.
