## Реализация

Общий RolloutLegend подключён в таблице планирования и ручном AssignmentModal. Используется существующий запрос шаблонов команды, без нового backend API. Отображаются этапы сохранённого шаблона и относительные сдвиги; одинаковые сдвиги объединяются. Легенда доступна в disabled-форме и для завершённой работы.

## Production UI

Подготовлен `tests/ui_rollout_legend.py`: настоящая авторизация, создание изолированных тестовых справочников и работы, desktop/mobile, клавиатура, оба места открытия, длинные названия/списки, прокрутка, закрытие и неизменность формы. Уникальный backup через SQLite API, гарантированная остановка собственного backend, восстановление через SQLite API с checkpoint, quick_check и сравнением логического digest.

После освобождения порта пользователем сценарий успешно выполнен. Проверены четыре сочетания: таблица/назначение × desktop 1440×1000/mobile 390×844. В каждом проверены группировка, длинные названия, прокрутка и отсутствие горизонтального/вертикального выхода всплывашки за viewport. Открытие таблицы проверено через Enter, закрытие — через Escape; в назначении — через кнопку закрытия внутри легенды. Скриншоты desktop-table-top.png и mobile-assignment-top.png просмотрены вручную.

В ходе проверки добавлена отдельная закреплённая кнопка закрытия легенды и ограничение высоты 40dvh: длинная легенда может перекрыть исходный значок, поэтому закрытие должно быть доступно внутри неё после прокрутки.

Ограничение существующей таблицы: при 390 px закреплённая колонка работы перекрывает ячейки дат. Мобильная легенда таблицы проверена непосредственно на телефоном viewport; для проверки легенды назначения само окно открывалось на desktop с последующим сужением до mobile. Исправление существующей таблицы не входит в это изменение.

## Уточнение компактности

По запросу пользователя блоки одного этапа перечисляются через запятую вместо отдельных строк; перенос длинного текста сохраняется. Component-тест проверяет строку «Б, В»; 8 тестов RolloutLegend прошли. Production UI-сценарий адаптирован к перечислению через запятую, но его повторный запуск остановлен до backup/изменений БД: порт 5093 снова занят чужим процессом. Предыдущий успешный UI-прогон относится к отображению блоков отдельными строками.
