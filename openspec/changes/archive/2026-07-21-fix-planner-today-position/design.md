## Context

`PlanningPage` запускает запрос списка работ, а затем — зависящие от полученных `taskIds` запросы назначений и зависимостей. Сейчас `taskData` сразу становится источником строк таблицы, поэтому React успевает отрисовать строки без назначений и зависимостей. Эффект центрирования следит за несколькими наборами данных, но первый успешный вызов `scrollGridToToday` снимает флаг ожидания до стабилизации содержимого таблицы.

## Goals / Non-Goals

**Goals:**

- Не монтировать planning grid до готовности данных текущей страницы, влияющих на таблицу.
- Показывать понятный индикатор загрузки на месте таблицы.
- Выполнять начальное центрирование только для полностью сформированной таблицы.
- Корректно обрабатывать страницу без работ, для которой зависимые запросы намеренно не запускаются.

**Non-Goals:**

- Объединение backend endpoints в один запрос.
- Блокировка всей страницы, фильтров и выбора команды.
- Изменение фонового обновления уже показанных данных после mutations.

## Decisions

1. `PlanningPage` будет использовать query-состояния (`data`, `isPending`, `isError`) основных запросов вместо вывода готовности только из наличия массивов. Таблица считается готовой после успешной загрузки работ и, если на странице есть работы, назначений и зависимостей. Справочник нерабочих дней также должен быть завершён, поскольку влияет на доступность ячеек. Запрос статистики `todayActive` не входит в барьер таблицы, так как не формирует её строки или ячейки.

2. До готовности вместо веток `Empty`/`Table` внутри карточки выводится Ant Design `Spin`. Фильтры и действия страницы остаются видимыми; это сохраняет контекст и позволяет пользователю изменить условия загрузки.

3. Для нулевого результата зависимые queries остаются disabled, а readiness считается достигнутым сразу после завершения tasks-query и справочника нерабочих дней. После этого показывается настоящее `Empty`, а не бесконечный spinner.

4. Центрирование связывается с итоговым признаком готовности planning grid. Флаг `pendingCenterRef` сбрасывается только после успешного поиска DOM-ячеек в готовой таблице; при изменении команды, периода, серверного поиска, статуса завершённости или страницы он устанавливается повторно.

5. Ошибка обязательного запроса завершает loading-состояние и показывает ошибку вместо частичной таблицы. Повторные фоновые refetch уже успешно показанного набора не должны скрывать таблицу, чтобы mutations не вызывали лишнего мерцания.

## Risks / Trade-offs

- [Risk] Последовательность tasks → assignments/deps увеличивает время до первого появления таблицы. → Индикатор загрузки явно сообщает о работе; объединение API не требуется для небольшого UI-исправления.
- [Risk] Неверная трактовка disabled query для пустой страницы оставит вечный spinner. → Готовность зависимых данных вычисляется с отдельной веткой `taskIds.length === 0`.
- [Risk] Эффект центрирования может выполниться до commit DOM. → Эффект зависит от готовности и успешности данных и сбрасывает флаг только при фактическом нахождении grid и ячейки сегодняшней даты.
