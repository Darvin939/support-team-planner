## Why

Предложение завершить работу теряется после массового сохранения и перезагрузки страницы, а незавершённые дубли успешно выполненных блоков мешают готовности. Теперь шаблон закреплён в самой работе, поэтому готовность можно устойчиво вычислять по успешному покрытию его блоков.

## What Changes

- Считать каждый блок выполненным при наличии хотя бы одного неудалённого назначения `success` с этим блоком; остальные попытки не блокируют готовность.
- Использовать текущий состав сохранённого шаблона работы и всю историю назначений независимо от диапазона планирования.
- Повторно вычислять готовность после одиночных и массовых изменений назначений, удаления, отмены и выбора шаблона работы.
- Показывать доступное действие «Завершить работу» при загрузке готовой работы без автоматического открытия окна; после появления готовности вследствие действия пользователя показывать подтверждение.
- Сохранять доступное действие после отказа; использовать существующий переход в `done` и права редактора/администратора.
- Удалить прежнюю проверку статусов всех затрагивающих шаблон назначений и зависимость предложения только от перехода одного назначения в `success`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `template-driven-task-completion`: успешное покрытие блоков, устойчивое состояние готовности и подтверждение после изменения данных.

## Impact

Backend DAO и API чтения работ/изменения назначений, модели API; frontend-модели, invalidation запросов, действия строки планирования и модальное подтверждение. Потребуются backend-тесты, Vitest + React Testing Library и production-сценарий Python + Playwright. Изменение схемы БД и перенос существующих данных не требуются; Python остаётся совместимым с 3.9.
