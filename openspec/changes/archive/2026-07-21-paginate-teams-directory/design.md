## Context

`TeamsTab` использует `useTeams()` и рендерит весь доступный список карточками. Тот же `useTeams()` и тот же `/api/teams` нужны многим другим разделам как полный справочник, поэтому нельзя безусловно заменить массив на пагинированный объект. Backend уже умеет ограничивать команды эффективным доступом пользователя, а frontend имеет готовые шаблоны пагинации и debounce на вкладке пользователей.

## Goals / Non-Goals

**Goals:**

- Перевести административный список команд на компактную таблицу.
- Фильтровать и пагинировать команды на backend после применения командного доступа.
- Переиспользовать общие frontend-механизмы пагинации и debounce.
- Не нарушить существующие вызовы полного справочника команд и CRUD.

**Non-Goals:**

- Изменение правил доступа к командам или ролей, которым доступна вкладка.
- Поиск по шаблонам, сортировка колонок или массовые действия.
- Изменение формы создания и редактирования команды.

## Decisions

1. `GET /api/teams` сохраняет два режима, как `/api/users`: без `offset`, `limit`, `search` возвращает прежний массив; при наличии хотя бы одного параметра возвращает `{teams, total}`. Это сохраняет совместимость всех текущих селекторов и страниц без создания второго endpoint.
2. DAO получает отдельную функцию пагинированного списка. Она сначала формирует область доступных команд, затем применяет регистронезависимый поиск по подстроке имени, считает `total`, применяет `LIMIT/OFFSET` и только для выбранной страницы загружает шаблоны. Это не раскрывает количество недоступных команд и не выполняет лишнюю работу.
3. `useTeams()` остаётся неизменным для полного справочника. Новый `usePaginatedTeams(offset, limit, search)` использует отдельный query key и пагинированный контракт.
4. `TeamsTab` повторяет UX `UsersTab`: debounce 350 мс, `DEFAULT_PAGE_SIZE`, `PAGE_SIZE_OPTIONS`, возврат на предыдущую страницу после удаления последней строки и сброс на первую страницу при изменении поиска.
5. Таблица содержит «Название», «Шаблоны» и «Действия». Шаблоны остаются тегами с переносом; действия и модальная форма сохраняют текущие обработчики.
6. На вкладках команд и пользователей кнопка добавления и поиск размещаются в одном `Space` с `display: flex`, `width: 100%` и нижним отступом 16 px. Поиск получает доступную ширину до своего `maxWidth`, а если кнопка недоступна по роли, панель корректно содержит только поиск. Это устраняет разрыв вертикального ритма и выравнивает UX двух справочников.

## Risks / Trade-offs

- [Risk] Двойной формат одного endpoint усложняет типизацию. → Разделить hooks и response-интерфейсы, а переключение формата определять только наличием query-параметров.
- [Risk] Инвалидация `['teams']` должна обновлять и полный, и пагинированный список. → Сохранить общий префикс query key `['teams']`.
- [Risk] Удаление последней строки страницы оставит пустую страницу. → Применить тот же переход на предыдущую страницу, что используется в `UsersTab`.
- [Risk] Большое число шаблонов расширит строку таблицы. → Использовать `Space wrap`/теги и горизонтальный scroll.
- [Risk] На узком экране inline-панель может не помещаться. → Разрешить `Space wrap`, чтобы поиск переносился целиком, сохраняя нижний отступ до таблицы.
