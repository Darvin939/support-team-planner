## ADDED Requirements

### Requirement: Команды отображаются в таблице
Система SHALL отображать команды на вкладке «Команды» в Ant Design `Table` с колонками «Название», «Шаблоны» и «Действия», сохраняя операции создания, редактирования и удаления.

#### Scenario: Открытие вкладки команд
- **WHEN** пользователь открывает вкладку «Команды»
- **THEN** каждая строка таблицы показывает название команды, её разрешённые шаблоны и доступные действия

#### Scenario: Команда не имеет шаблонов
- **WHEN** у команды нет разрешённых шаблонов
- **THEN** колонка «Шаблоны» показывает нейтральное пустое значение

### Requirement: Список команд имеет серверную пагинацию
Система SHALL применять `offset` и `limit` на backend и SHALL возвращать общее число доступных команд, соответствующих текущему поиску.

#### Scenario: Переход на другую страницу
- **WHEN** пользователь меняет страницу пагинации
- **THEN** frontend запрашивает соответствующий `offset`, а backend возвращает только строки этой страницы

#### Scenario: Изменение размера страницы
- **WHEN** пользователь выбирает 10, 20, 50 или 100 строк
- **THEN** frontend сбрасывает список на первую страницу и запрашивает выбранный `limit`

#### Scenario: Удаление последней строки страницы
- **WHEN** после удаления текущая страница становится пустой, но совпадающие команды ещё существуют
- **THEN** frontend переходит на предыдущую страницу

### Requirement: Поиск команд выполняется до пагинации
Система SHALL фильтровать доступные команды на backend по регистронезависимой подстроке названия до подсчёта общего числа и применения пагинации.

#### Scenario: Поиск по части названия
- **WHEN** пользователь вводит часть названия команды
- **THEN** таблица показывает все доступные совпадения независимо от их исходной страницы

#### Scenario: Очистка поиска
- **WHEN** пользователь очищает поисковую строку
- **THEN** frontend возвращается на первую страницу полного доступного списка

### Requirement: Полный список команд остаётся совместимым
Система SHALL сохранять прежний формат полного массива для `GET /api/teams` без параметров пагинации и поиска.

#### Scenario: Существующий потребитель запрашивает справочник
- **WHEN** frontend вызывает `/api/teams` без `offset`, `limit` и `search`
- **THEN** backend возвращает прежний массив всех доступных пользователю команд с разрешёнными шаблонами

### Requirement: Действие добавления и поиск образуют единую панель
Система SHALL размещать кнопку добавления и поле поиска в одной адаптивной inline-панели с визуальным отступом до таблицы на вкладках «Команды» и «Пользователи».

#### Scenario: Панель команд
- **WHEN** пользователь открывает вкладку «Команды» на экране достаточной ширины
- **THEN** кнопка «Добавить команду» и поиск отображаются в одной строке, а таблица отделена от панели вертикальным отступом

#### Scenario: Панель пользователей для администратора
- **WHEN** администратор открывает вкладку «Пользователи» на экране достаточной ширины
- **THEN** кнопка «Добавить пользователя» и поиск отображаются в одной строке

#### Scenario: Панель пользователей без кнопки добавления
- **WHEN** неадминистратор открывает вкладку «Пользователи»
- **THEN** поиск сохраняет положение и отступ до таблицы без пустого места для скрытой кнопки

#### Scenario: Узкий экран
- **WHEN** ширины экрана недостаточно для кнопки и поиска в одной строке
- **THEN** панель переносит элементы без наложения и сохраняет отступ до таблицы
