## ADDED Requirements

### Requirement: Data access разделён по доменным границам

Backend SHALL размещать DAO-функции в доменных модулях, сохраняя единый connection/transaction layer и наблюдаемое поведение существующих роутеров.

#### Scenario: DAO-группа перенесена
- **WHEN** функции одного домена извлекаются из монолитного модуля
- **THEN** существующие API-контракты, транзакции и тестовые сценарии остаются неизменными

#### Scenario: Роутер использует data access
- **WHEN** endpoint вызывает DAO-функцию
- **THEN** соединение текущего HTTP-запроса переиспользуется по существующей модели lifecycle

#### Scenario: DAO проектируется для будущего backend
- **WHEN** доменный DAO выделяется из монолитного модуля
- **THEN** его публичная граница не зависит от SQLite-specific connection/cursor API, а диалектные операции остаются внутри database backend abstraction

#### Scenario: PostgreSQL ещё не подключается
- **WHEN** завершается декомпозиция текущего SQLite data-access
- **THEN** система не содержит неиспользуемых PostgreSQL-драйверов, конфигурации, миграций, адаптеров или условных веток

### Requirement: Составные операции назначений атомарны

Backend SHALL предоставлять bulk assignment operations для составных пользовательских действий, а frontend SHALL вызывать соответствующую операцию одним HTTP-запросом.

#### Scenario: Автоназначение сохраняет несколько дат
- **WHEN** пользователь подтверждает автоназначение по шаблону
- **THEN** backend валидирует и сохраняет весь набор в одной транзакции либо откатывает весь набор

#### Scenario: Массовое удаление выполняется
- **WHEN** пользователь удаляет выбранный набор назначений
- **THEN** frontend не выполняет цикл одиночных DELETE-запросов, а использует согласованный bulk-контракт

#### Scenario: Bulk payload меняется
- **WHEN** публичный bulk assignment contract добавляется или изменяется
- **THEN** frontend и backend обновляются в рамках одной группы изменения

### Requirement: Повторяющиеся связанные данные загружаются пакетно

DAO SHALL избегать N+1-запросов при сборке пользователей с командами и шаблонов с блоками.

#### Scenario: Загружена страница пользователей
- **WHEN** backend формирует страницу нескольких пользователей
- **THEN** связи пользователей с командами загружаются пакетно, а не отдельным запросом на пользователя

#### Scenario: Загружены шаблоны команды
- **WHEN** backend формирует список шаблонов с блоками
- **THEN** блоки всех шаблонов загружаются пакетно

### Requirement: Ошибки data-access остаются диагностируемыми

Backend SHALL преобразовывать ожидаемые ограничения данных в явные доменные исключения и SHALL NOT маскировать неожиданные DB-ошибки значениями `False` или `None`.

#### Scenario: Нарушено ожидаемое ограничение
- **WHEN** запись конфликтует с уникальным или доменным ограничением
- **THEN** роутер получает типизированную причину и возвращает стабильную API-ошибку

#### Scenario: Возникла неожиданная DB-ошибка
- **WHEN** DAO не может классифицировать исключение как ожидаемую бизнес-ошибку
- **THEN** исключение доступно общему логированию и error handler
