## Context

`OverdueNotifications` монтируется внутри `AppShell`, поэтому `useOverdueAssignments` запускается на каждой защищённой странице и повторяется каждые пять минут. Hook запрашивает `/api/active-assignments/0` без `limit`, отбрасывает `total`/`stats` и сохраняет в TanStack Query весь массив `items`. На большой базе это создаёт неограниченные расходы SQL-выборки, сериализации, сети, JSON parsing и памяти браузера.

Endpoint уже принимает `offset` и `limit` и при этом возвращает точный `total`. Следовательно, проблему можно решить без нового count endpoint и без двух последовательных запросов.

## Goals / Non-Goals

**Goals:**

- Ограничить payload уведомлений 30 элементами.
- Сохранить точный badge общего количества.
- Явно сообщать пользователю о сокращённом preview.
- Не менять период, сортировку и переход по элементу.

**Non-Goals:**

- Пагинация или бесконечная прокрутка внутри popover.
- Оптимизация SQL `COUNT(*)` и индексов в рамках этого изменения.
- Изменение экрана Statistics, использующего тот же endpoint с собственной пагинацией.

## Decisions

1. Ввести frontend-константу `OVERDUE_PREVIEW_LIMIT = 30`. `useOverdueAssignments` добавляет `offset=0&limit=30` и возвращает response `{items, total}`, а не преобразует его в массив.

2. Использовать отдельный query key, включающий назначение preview и limit. Это исключает коллизию с прежним cached-массивом и другими потребителями `active-assignments`.

3. `OverdueNotifications` использует `data.items` для списка, `data.total` для badge и заголовка. При `total > items.length` под списком выводится «Показаны первые 30 из N».

4. Не выполнять предварительный count-запрос. Один ограниченный endpoint-вызов уже возвращает и preview, и точный total, поэтому двухфазная схема добавила бы latency и состояние гонки без уменьшения нагрузки.

## Risks / Trade-offs

- [Risk] Точный `COUNT(*)` на миллионах строк всё ещё может быть медленным. → Сначала устраняется критическая проблема неограниченного payload; SQL-план измеряется отдельно и при необходимости оптимизируется индексом или capped count.
- [Risk] Пользователь не увидит назначения после первых 30. → Popover явно маркирует preview; текущая функция не является полноценным журналом и сохраняет переход для каждого показанного элемента.
- [Risk] Изменение формы данных hook сломает типы потребителя. → `OverdueNotifications` обновляется в том же изменении, а production build проверяет контракт.
