## ADDED Requirements

### Requirement: Работа определяет обязательный сегмент и шаблон раскатки
Система SHALL требовать при создании работы явный выбор существующего сегмента и существующего шаблона раскатки, разрешённого команде и принадлежащего этому сегменту. Форма MUST не подставлять первый сегмент или шаблон автоматически. Read API работы SHALL возвращать сохранённые идентификатор и название шаблона, а сохранение работы MUST атомарно включать шаблон и его историю вместе с остальными полями и зависимостями.

#### Scenario: Создание с корректным выбором
- **WHEN** пользователь выбирает сегмент и разрешённый команде шаблон этого сегмента и сохраняет работу
- **THEN** работа сохраняется с обоими значениями, история создания включает шаблон, а API возвращает идентификатор и название шаблона

#### Scenario: Выбор отсутствует или некорректен
- **WHEN** новая работа сохраняется без сегмента или шаблона, с несуществующим шаблоном, шаблоном другого сегмента либо не разрешённым команде
- **THEN** сохранение отклоняется без частичной записи работы и зависимостей

#### Scenario: Пользователь меняет сегмент до назначений
- **WHEN** пользователь меняет доступное для редактирования поле сегмента
- **THEN** форма очищает прежний шаблон и предлагает только разрешённые команде шаблоны нового сегмента

#### Scenario: Изменение шаблона отражается в истории
- **WHEN** пользователь допустимо заменяет шаблон работы
- **THEN** система записывает старое и новое значения в историю работы вместе с прочими изменениями сохранения

### Requirement: Существующие работы сохраняют выбор и допускают заполнение отсутствующего шаблона
Система SHALL сохранять существующие сегменты и ссылки на шаблоны при обновлении приложения без автоматического выбора. Старой нетерминальной работе без шаблона SHALL разрешаться первоначальное заполнение подходящим разрешённым шаблоном при неизменном сегменте даже при наличии назначений. Сохранение прочих полей старой работы без шаблона SHALL оставаться доступным. Очистка уже выбранного шаблона MUST отклоняться.

#### Scenario: Обновление существующих данных
- **WHEN** приложение обновляется для базы с заполненными и пустыми ссылками на шаблоны
- **THEN** сегменты и ссылки остаются прежними, NULL не заполняется автоматически

#### Scenario: Однократное заполнение с назначениями
- **WHEN** у старой нетерминальной работы есть назначения и нет шаблона, пользователь выбирает разрешённый шаблон текущего сегмента
- **THEN** система сохраняет шаблон, оставляет сегмент прежним и далее блокирует замену шаблона до удаления всех назначений

#### Scenario: Изменение описания старой работы
- **WHEN** пользователь меняет описание старой нетерминальной работы без шаблона и не меняет её сегмент
- **THEN** изменение сохраняется без автоматического заполнения шаблона

#### Scenario: Исторический шаблон больше не подходит
- **WHEN** сохранённый шаблон не соответствует сегменту работы или более не разрешён команде
- **THEN** система сохраняет и отображает прежнюю связь, допускает изменение несвязанных полей, а автопланирование объясняет недоступность шаблона

#### Scenario: Очистка выбранного шаблона
- **WHEN** клиент пытается явно очистить уже сохранённый шаблон
- **THEN** API отклоняет сохранение без изменения работы
