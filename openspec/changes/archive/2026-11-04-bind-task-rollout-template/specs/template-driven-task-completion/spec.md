## MODIFIED Requirements

### Requirement: Автоназначение сохраняет выбранный шаблон работы
Система SHALL использовать для автоназначения шаблон, заранее сохранённый в работе, без отдельного выбора в форме назначений. Сохранение автоназначений MUST быть атомарным и MUST не изменять связь работы с шаблоном. Название требования сохранено для совместимости спецификации; выбор переносится в форму работы.

#### Scenario: Успешное автоназначение по шаблону
- **WHEN** пользователь включает и подтверждает автоназначение работы с подходящим непустым разрешённым шаблоном
- **THEN** интерфейс показывает раскладку по сохранённому шаблону без Select шаблона, система сохраняет назначения и оставляет связь работы прежней

#### Scenario: Ошибка массового сохранения
- **WHEN** хотя бы одно назначение автоназначения не может быть сохранено
- **THEN** система не сохраняет частичные назначения и не изменяет шаблон работы

#### Scenario: Шаблон отсутствует или недоступен
- **WHEN** у работы нет шаблона, он пуст, не соответствует сегменту или более не разрешён команде
- **THEN** автоназначение недоступно с объяснением причины, а ручное планирование остаётся доступным по существующим правилам

#### Scenario: Устаревший клиент пытается заменить шаблон
- **WHEN** массовый запрос передаёт `template_id`, не совпадающий с сохранённым шаблоном единственной целевой работы, либо у работы шаблон отсутствует
- **THEN** API отклоняет весь запрос, не изменяя назначения и шаблон

#### Scenario: Устаревший клиент передаёт прежний шаблон
- **WHEN** массовый запрос одной работы передаёт `template_id`, равный сохранённому шаблону
- **THEN** API может принять запрос по обычным правилам сохранения назначений, не перезаписывая шаблон работы

#### Scenario: Ручное покрытие сохранённого шаблона
- **WHEN** назначения созданы вручную и полностью успешно покрывают сохранённый шаблон
- **THEN** существующая проверка готовности и подтверждение завершения используют этот же шаблон
