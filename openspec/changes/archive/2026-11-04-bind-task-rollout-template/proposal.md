## Why

Сегмент сейчас можно изменить даже после создания назначений, а шаблон раскатки выбирается отдельно при каждом автоназначении. Работа должна заранее определять сегмент и шаблон, чтобы планирование использовало согласованную конфигурацию и не позволяло подменять её при наличии назначений.

## What Changes

- Новая работа требует явного выбора сегмента и обязательного шаблона из разрешённых команде шаблонов этого сегмента.
- Работа хранит выбранный шаблон; автопланирование использует его без отдельного поля выбора.
- Любое неудалённое назначение, включая статус «Новый» или «Отменено», блокирует изменение сегмента и шаблона в UI и API. После удаления всех назначений поля разблокируются с учётом существующих запретов терминальных работ.
- Существующие шаблоны работ сохраняются. Старым работам без шаблона разрешено однократное заполнение даже при наличии назначений; до заполнения автопланирование недоступно.
- Используемый работами шаблон нельзя удалить или перенести в другой сегмент. Название, состав блоков и смещения остаются редактируемыми.
- Короткие параметры формы сгруппированы в две компактные Card без заголовков: критичность с ПСИ, затем сегмент с шаблоном; на мобильном поля складываются вертикально.
- **BREAKING**: создание работы требует шаблон; массовое сохранение назначений больше не выбирает и не заменяет шаблон работы.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `task-management`: обязательный сегмент и шаблон работы, read/write API, переход существующих данных.
- `task-edit-locking`: блокировка сегмента и шаблона при неудалённых назначениях и исключение для первоначального заполнения старых работ.
- `template-driven-task-completion`: использование сохранённого в работе шаблона при автоназначении без его подмены массовым API.
- `settings-work-reference-directory`: защита удаления и смены сегмента используемых шаблонов.
- `task-modal-layout`: компактная группировка параметров работы и размещение ПСИ рядом с критичностью.

## Impact

Backend: модели API, DAO работ, назначения, справочник шаблонов, транзакционная валидация и история работы. Frontend: форма работы, состояние модального окна назначений, автопланирование, hooks, типы, отображение ошибок справочника. Проверки: backend regression-тесты, Vitest + React Testing Library, production UI-сценарий с реальным входом и WAL-безопасным backup/restore. Переиспользуется `tasks.completion_template_id`; автоматический выбор шаблонов для старых работ не выполняется. Изменения Python совместимы с 3.9.
