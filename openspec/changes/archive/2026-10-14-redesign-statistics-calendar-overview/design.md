## Context

Сейчас `StatisticsPage` содержит отдельные таблицы сегодняшнего дня и периода, а подневные агрегаты отображаются только внутри RangePicker. `useStatisticsData` уже предоставляет серверные агрегаты и пагинированные назначения. Группировать строки текущей страницы таблицы для календаря нельзя: результат будет неполным.

## Goals / Non-Goals

**Goals:** сделать количества сразу видимыми, обеспечить выбор дня и полную детализацию, разделить дневной и периодный сценарии, сохранить доступность и корректность асинхронных данных.

**Non-Goals:** статистика завершённых/отменённых работ, оценка трудозатрат и перегрузки, редактирование назначений из календаря, новые API, изменение схемы БД, новые зависимости и изменение глобального поведения фильтра периода.

## Decisions

### Компоновка

Последовательность: заголовок → общий фильтр команд → «По дням / За период» → содержимое режима. По дням: заголовок «Активные работы по дням», навигация месяца и «Сегодня», компактная сетка, строка выбранной даты с количеством и «К списку работ», сводка статусов/критичности, полная таблица. В периоде: обычный RangePicker, сводка и таблица. Отдельный блок «На сегодня» удаляется.

Полная таблица располагается под календарём: вариант со списком справа отклонён после согласования необходимости всех полей. Диаграмма и скрытая вкладка календаря не нужны для основного сценария поиска даты.

### Календарь

Один месяц, неделя с понедельника, семь колонок, компактные ячейки с номером дня и точным количеством. Использовать компоненты и токены текущего Ant Design; сетку допускается реализовать отдельным React-компонентом без новой библиотеки. Крайние позиции соседних месяцев оставить пустыми и неинтерактивными: это исключает дополнительную неоднозначность навигации. Запрос агрегатов покрывает начало–конец отображаемого месяца вместо прежнего окна двух панелей. Удалить старый `cellRender`, бейджи и стили их скрытия.

Сегодня отмечено обводкой, выбранная дата — фоном и доступным состоянием выбора; признаки различимы при совпадении. Числа не сокращаются до `9+`, ноль приглушён. Семантические кнопки дат имеют доступное имя с полной датой и количеством; Enter/Space выбирают день, фокус видим. Цвет не является единственным носителем информации. На мобильном сохраняются семь колонок, заголовок переносится, широкая таблица прокручивается внутри контейнера.

### Состояние и переходы

Хранить независимо `mode`, отображаемый месяц, выбранный день и диапазон периода. При новом открытии страницы режим дневной и выбран сегодня. Переключение режимов сохраняет оба набора дат в состоянии страницы; отдельное долговременное сохранение режима не требуется. Фильтр команд и существующее хранение диапазона через `useDateRangeFilter` сохраняются, включая его текущие ограничения и сброс при очистке.

При навигации в другой месяц установить состояние ожидания автоматического выбора и запросить его агрегаты. После успешного ответа выбрать минимальную дату месяца с ненулевым количеством; если таких дат нет — первое число. Текущий месяц и кнопка «Сегодня» выбирают сегодня независимо от количества. Пока автоматический выбор ожидается, не показывать таблицу старой даты под заголовком нового месяца. При ошибке показать повтор запроса и разрешить ручной выбор даты.

Ручной выбор отменяет ожидающий автоматический выбор. Ответ предыдущего месяца/фильтра, фоновое обновление и повторный рендер не меняют выбранный пользователем день. Смена команд сохраняет выбранную дату и обновляет её данные, даже если она стала пустой; если выбор ещё ожидался, использовать агрегаты новых команд. Переход в период при незавершённом выборе не сбрасывает дневной контекст.

### Данные и детализация

Переиспользовать endpoint подневных агрегатов и endpoint активных назначений. Для дня передавать одинаковые начало и конец, для периода — его границы. Запрашивать детализацию активного режима; запросы и таблица должны быть связаны ключами с актуальными датами и командами. Сохранять серверные totals и сводки, не вычислять их по странице items. Смена дня, периода или команд сбрасывает соответствующую пагинацию. Размер страницы общий, номера страниц независимы.

Все поля текущей таблицы сохраняются: работа, команда, критичность, блок, статус, исполнитель, комментарий; в периоде также дата. Над таблицей явно указана дата или диапазон. Подпись поясняет, что учитываются активные назначения: одна работа на нескольких датах учитывается на каждой из них; итог периода не обещает количество уникальных задач.

Первичная загрузка счётчиков показывает индикатор вместо нулей; успешный пустой ответ означает нули. Ошибка календаря имеет локальное сообщение и повтор запроса. Загрузка/ошибка детализации не отображается как «Нет активных работ». Данные других команд и дат не используются как placeholder. При обновлении того же ключа кэш допустим с индикатором обновления.

Выбор дня не прокручивает страницу. «К списку работ» явно переводит к заголовку детализации и делает его доступным для клавиатурного пользователя; анимация учитывает reduced motion.

## Risks / Trade-offs

- Асинхронный автоматический выбор может перезаписать ручной → отменяемый pending intent и привязка к месяцу/командам, тесты гонок.
- Полная таблица ниже календаря может оказаться за экраном → компактный календарь и явная кнопка перехода.
- Ноль можно спутать с неизвестными данными → разные состояния загрузки, ошибки и успешного ответа.
- Существующий диапазон связан с общим хранением фильтров → сохранять текущий контракт, не менять другие страницы.

## Migration Plan

Реализовать frontend и тесты, собрать production frontend и выполнить UI-проверки. Перед UI-тестом создать уникальный SQLite backup через backup API; после изменений БД остановить backend, восстановить через backup API и выполнить checkpoint. Python-сценарии совместимы с 3.9, UTF-8 без BOM; остановить только процессы текущего теста. После отдельного разрешения синхронизировать основные спецификации, затем после отдельного разрешения архивировать изменение. Откат frontend не требует миграции данных.
