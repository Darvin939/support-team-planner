## Context

В `usePlanningColumns.tsx` есть два `Dropdown` с `contextMenu` trigger: в ячейке «Работа» и в чипе назначения. Клик вне popup закрывает `Dropdown`, но затем доходит до обработчика элемента под курсором и может открыть модальное окно работы или назначения.

## Goals / Non-Goals

**Goals:**

- Поглощать ровно один внешний клик, который закрывает любое контекстное меню таблицы.
- Не изменять обычные клики при закрытом меню и действия внутри menu popup.

**Non-Goals:**

- Не менять вид, состав или позиционирование меню.

## Decisions

- В `usePlanningColumns` используются общие ref: признак открытого planning-context-dropdown и признак поглощения следующего клика.
- Оба `Dropdown.onOpenChange` синхронизируют общий open-ref. Ant Design закрывает предыдущий popup при открытии другого, поэтому булевого признака достаточно.
- Document-level `pointerdown` capture listener при открытом menu помечает внешний клик для поглощения. Клики внутри `.ant-dropdown` не помечаются.
- Поглощение выполняется в общем capture-обработчике planning grid через `preventDefault`, `stopPropagation` и `stopImmediatePropagation`, чтобы не допустить ни одно действие лежащего под курсором элемента. При этому меню закрывается явно через контролируемый open state.
- Состояние открытого menu хранит id/тип Dropdown, чтобы оба menu были контролируемыми и взаимоисключающими.

## Risks / Trade-offs

- [Risk] Полное поглощение pointerdown может помешать outside-click логике Ant Design → Меню закрывается явно контролируемым state до поглощения.
- [Risk] Общий механизм может затронуть клики внутри menu → Явно исключить `.ant-dropdown` и проверить выбор пункта UI-тестом.
