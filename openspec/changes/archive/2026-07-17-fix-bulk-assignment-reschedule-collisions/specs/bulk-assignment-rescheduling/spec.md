## ADDED Requirements

### Requirement: Проверка групповых коллизий использует итоговое состояние расписания
Интерфейс планирования и сервер MUST проверять групповой перенос относительно состояния, которое возникнет после перемещения всех назначений из переданной группы. Исходная ячейка, занятая назначением из той же группы, SHALL считаться освобождаемой, а ячейка с назначением вне группы SHALL оставаться недоступной.

#### Scenario: Перенос в ячейку, освобождаемую той же группой
- **WHEN** выбранные назначения одной задачи занимают дни 1 и 3, а группа сдвигается так, что первое назначение попадает в день 3, а второе перемещается дальше
- **THEN** день 3 считается доступным, предварительная проверка разрешает перенос и группа может быть отправлена на сервер

#### Scenario: Целевая ячейка занята назначением вне группы
- **WHEN** хотя бы одна целевая ячейка занята назначением, не входящим в переданную группу
- **THEN** предварительная проверка запрещает перенос и группа не отправляется на сервер

#### Scenario: Два выбранных назначения попадают в одну ячейку
- **WHEN** два переданных перемещения приводят к одной паре задачи и даты
- **THEN** группа отклоняется из-за коллизии

#### Scenario: Целевая дата выходит за поддерживаемый диапазон
- **WHEN** сдвиг выбранной группы создаёт дату вне диапазона 2000–2099 годов
- **THEN** предварительная проверка запрещает перенос и группа не отправляется на сервер

### Requirement: Групповой перенос сохраняется атомарно
Система SHALL сохранять допустимый групповой перенос в одной транзакции базы данных, соблюдая ограничение уникальности активного назначения для пары задачи и даты. Все переданные назначения MUST перейти на итоговые даты либо ни одно из них не должно измениться.

#### Scenario: Цепочка сохраняется независимо от порядка обновления
- **WHEN** допустимая группа содержит перенос в исходную ячейку другого участника той же группы
- **THEN** все назначения сохраняются на итоговых датах без временного нарушения уникальности

#### Scenario: Одно из перемещений не проходит проверку или сохранение
- **WHEN** одно переданное перемещение недопустимо, неавторизовано, отсутствует, заблокировано или не может быть сохранено
- **THEN** API возвращает JSON-ошибку и ни одно назначение группы не изменяется

#### Scenario: Успешный перенос записывает историю
- **WHEN** групповой перенос успешно фиксируется
- **THEN** для каждого изменённого назначения создаётся запись аудита от исходной даты к итоговой с пользователем текущей сессии в `changed_by`

### Requirement: Массовый перенос соблюдает действующие правила назначений
Операция массового переноса MUST получать назначения из базы данных и применять те же ограничения роли и статуса, что и одиночный перенос. Переданные клиентом данные SHALL NOT переопределять задачу или другие сохранённые поля назначения.

#### Scenario: Обычный пользователь передаёт назначение в продвинутом статусе
- **WHEN** пользователь с ролью `user` отправляет группу с назначением, статус которого отличается от `new`
- **THEN** вся группа отклоняется и ни одно назначение не изменяется

#### Scenario: Сохранённая принадлежность назначения отличается от предположения клиента
- **WHEN** загруженное сервером назначение относится не к той задаче, которую предполагает клиент
- **THEN** сервер использует сохранённую задачу, а клиент не может перенести назначение в другую задачу через массовый маршрут

### Requirement: Подсветка группового переноса соответствует допустимым на сервере целям
Во время перетаскивания нескольких назначений интерфейс планирования SHALL вычислять все сдвинутые цели из зафиксированного снимка группы и SHALL помечать группу допустимой только тогда, когда её итоговая раскладка проходит правила коллизий и диапазона дат.

#### Scenario: Допустимая предварительная проверка цепочки
- **WHEN** указатель сдвигает выбранную группу в ячейки, освобождаемые другими участниками этой группы
- **THEN** все видимые целевые ячейки получают допустимую подсветку вместо красной рамки занятой ячейки

#### Scenario: Недопустимая предварительная проверка группы
- **WHEN** хотя бы одна сдвинутая цель конфликтует с внешним назначением, совпадает с другой итоговой целью или выходит за диапазон дат
- **THEN** конфликтующие видимые ячейки помечаются как недопустимые и отпускание мыши не вызывает массовый API

#### Scenario: Сервер отклоняет перенос после допустимой предварительной проверки
- **WHEN** расписание конкурентно изменилось и сервер отклонил переданную группу
- **THEN** интерфейс показывает сообщение об ошибке на русском, обновляет данные назначений и не сообщает о частично успешном переносе
