## Why

`GET /api/tasks/{team_id}` сейчас при `show_completed=true` возвращает в общую выборку все когда-либо завершённые и отменённые работы команды. По мере роста истории это делает основной экран планирования перегруженным и ухудшает производительность, одновременно не предоставляя удобного способа целенаправленно искать старые работы.

## What Changes

- Основная выборка планирования будет возвращать все активные работы и, по запросу пользователя, только работы, завершённые или отменённые за последние 30 дней.
- Для работ будет храниться дата завершения текущего жизненного цикла; при возобновлении работы дата очищается, при повторном завершении устанавливается заново.
- Появится отдельная архивная выборка завершённых и отменённых работ с серверной пагинацией, поиском и фильтрацией по периоду завершения.
- Получение одной работы по идентификатору будет вынесено в отдельный API, не зависящий от фильтров основной или архивной выборки.
- Неоднозначный параметр `show_completed` будет заменён явным режимом включения недавних завершённых работ; frontend будет переведён на новый контракт.
- Для существующих терминальных работ дата завершения будет по возможности восстановлена из истории смены статуса; работы без достоверной даты останутся доступны в полном архиве.
- Редакторы и администраторы смогут восстановить завершённую или отменённую работу непосредственно из архива, вернув её в активный статус без потери данных и назначений.

## Capabilities

### New Capabilities

- `task-lifecycle-visibility`: Правила видимости активных, недавно завершённых и архивных работ, хранение даты завершения и прямое получение работы по ID.

### Modified Capabilities

- `task-management`: Получение одной существующей неудалённой работы становится отдельной операцией API, независимой от списочных фильтров.

## Impact

- Backend: схема и миграции SQLite, запросы в `db/__init__.py`, маршруты FastAPI в `support_planner.py`.
- Frontend: hooks и query keys данных планирования, переключатель недавних завершённых работ, отдельный интерфейс архива, восстановление работы и прямое открытие работы по ID.
- API: изменяется контракт списочной выборки `/api/tasks/{team_id}` и добавляются endpoint архива, endpoint одной работы и отдельная операция восстановления.
- Тестирование: DAO/API-тесты миграции, фильтрации, пагинации и переходов статуса; production UI-тест сценариев планирования и архива через Python + Playwright.
