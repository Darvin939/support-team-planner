## Context

`JournalPage` уже получает структурированные `JournalItem[]`, но отображает каждую запись отдельной кликабельной карточкой. При двадцати строках на странице повторяющиеся поля не выровнены, а состояние загрузки query не показывается. Форматирование автора и текста изменения централизовано в `historyFormat` и должно остаться общим с историей сущностей.

## Goals / Non-Goals

**Goals:**

- сделать журнал компактной сканируемой таблицей;
- сохранить текущие фильтры, server-side offset pagination и открытие истории работы;
- показать loading и empty состояния;
- обеспечить использование на desktop и мобильной ширине.

**Non-Goals:**

- изменение API или SQL журнала;
- клиентская сортировка либо изменение порядка «новые сверху»;
- новые фильтры, экспорт или группировка записей;
- переработка модального окна истории задачи.

## Decisions

### Использовать Ant Design Table с внешней пагинацией

Таблица получает `data.items`, `loading`, `rowKey`, `pagination={false}` и `scroll={{x: ...}}`. Существующий `OffsetPagination` остаётся единственным управлением страницами, поэтому query key, offset и server-side total не меняются.

Альтернатива — встроенная пагинация Table. Она потребовала бы дополнительного преобразования page/offset и создала бы два источника состояния.

### Отобразить пять семантических колонок

Колонки: «Дата и время», «Работа», «Объект», «Изменение», «Автор». Значения автора и изменения продолжают вычисляться `formatChangedBy` и `formatHistoryText`. Тип объекта выводится локализованным тегом «Работа»/«Назначение», а удалённая работа сохраняет существующую метку.

### Сохранить переход через кликабельную строку

`onRow` открывает существующий `TaskHistoryModal` для `task_id`; курсор и hover должны визуально сообщать интерактивность. Отдельная колонка действий не нужна, поскольку текущее поведение — клик по всей карточке.

### Адаптировать ширину без потери данных

Таблица получает минимальную горизонтальную ширину и прокручивается на узких экранах. Колонка «Объект» скрывается на небольших breakpoint, поскольку тип уже читается из формулировки изменения; остальные данные остаются доступны через горизонтальный scroll. Длинные работа и изменение используют ellipsis с tooltip.

## Risks / Trade-offs

### Представить историю работы в модальном окне таблицей

`TaskHistoryModal` следует паттерну «Архива работ»: широкое модальное окно содержит Ant Design Table `size="small"` с колонками «Дата и время», «Изменение» и «Автор», встроенными loading/empty состояниями, горизонтальной прокруткой и существующей внешней `OffsetPagination`. Общий `HistoryEntries` не изменяется, чтобы компактная панель истории в планировании сохранила подходящий для неё формат.

### Унифицировать пагинацию основных страниц

Основные таблицы планирования, статистики и журнала используют общий `PagePagination`. Компонент принимает `current`, `pageSize`, `total` и единый `onChange`, а также централизует `PAGE_SIZE_OPTIONS`, отображение переключателя размера страницы, выравнивание и вертикальные отступы. Страницы сохраняют собственное состояние через `usePaginationState`, включая сброс на первую страницу при смене размера.

Журнал передаёт текущий `pageSize` в server-side query как `limit`, поэтому смена размера страницы не меняет API-контракт и сохраняет offset-навигацию. Компактная пагинация внутри модального окна истории остаётся на `OffsetPagination`, поскольку относится к отдельному ограниченному контексту.

### Закрепить заголовок таблицы журнала

Таблица журнала использует sticky header. На мобильной ширине `offsetHeader` равен `TOP_BAR_HEIGHT`, чтобы заголовок не перекрывался фиксированной верхней панелью; на desktop используется нулевой отступ. Это повторяет существующий паттерн таблицы планирования.

- [Горизонтальный scroll менее удобен на телефоне] → оставить ключевые колонки видимыми первыми и скрыть только избыточную колонку объекта.
- [Клик по тексту или будущей кнопке активирует строку] → сейчас интерактивных элементов в ячейках нет; при их появлении потребуется `stopPropagation`.
- [Сырой `changed_at` имеет backend-формат] → сохранить текущее представление в рамках behavior-preserving UI change; нормализацию даты оформить отдельно.
