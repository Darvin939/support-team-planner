## Context

`UsersTab` получает полный массив из `GET /api/users` и выводит его через Ant Design `List`. Тот же endpoint и hook используются в формах, где нужен полный список. Planning и Statistics дублируют одинаковые наборы размеров страницы.

## Goals / Non-Goals

**Goals:**

- Заменить `List` на таблицу с явными колонками и действиями.
- Добавить серверный поиск и пагинацию без регрессии полного списка для других UI.
- Устранить дублирование общих параметров пагинации.

**Non-Goals:**

- Изменение CRUD-форм и прав доступа.
- Сортировка колонок.
- Изменение схемы БД.

## Decisions

1. `GET /api/users` без `offset`, `limit` и `search` сохраняет старый ответ-массив. При передаче параметров endpoint возвращает `{ users, total }`. Это сохраняет совместимость с `AssignmentModal` и user-name hooks.
2. Добавить отдельный `usePaginatedUsers(offset, limit, search)` с query key, включающим все параметры. Поиск дебаунсится на frontend, но фильтруется в SQL до `LIMIT/OFFSET`.
3. SQL-поиск регистронезависимо сопоставляет подстроку с `login`, склеенным ФИО, raw-role и её русским названием.
4. Вынести `DEFAULT_PAGE_SIZE = 20` и `PAGE_SIZE_OPTIONS = ['10', '20', '50', '100']` в `frontend/src/lib/pagination.ts`; Planning, Statistics и UsersTab импортируют их.
5. После смены поиска или размера сбрасывать текущую страницу на 1. После удаления последней строки на непервой странице перейти на предыдущую.

## Risks / Trade-offs

- [Два формата ответа одного endpoint] → Режим явно определяется наличием query-параметров и закрывается двумя типизированными hooks.
- [SQLite `lower()` ограничен для Unicode] → Русские роли сопоставлять в backend с raw-role до SQL; для ФИО и логина использовать `LIKE`, как в текущих поисках проекта.
