## Purpose

Определяет выбор источника сертификата и ключа при запуске backend, использование HTTPS при рабочей паре и сохранение HTTP при недоступности обоих источников.

## ADDED Requirements

### Requirement: Приоритет смонтированной файловой пары
Система MUST принимать пути `SUPPORT_PLANNER_TLS_CERT_FILE` и `SUPPORT_PLANNER_TLS_KEY_FILE` из окружения или поддерживаемого dotenv-файла. При наличии полной пары PEM-файлов система MUST использовать их напрямую, без получения сертификата через Vault AppRole и без копирования смонтированных файлов во временный каталог.

#### Scenario: Deployment подготовил сертификат и ключ
- **WHEN** оба настроенных файла существуют, читаются и образуют корректную PEM-пару
- **THEN** backend использует эти файлы, а прямые Vault-запросы не выполняются

#### Scenario: Пути заданы в dotenv
- **WHEN** указанный через `SUPPORT_PLANNER_ENV_FILE` dotenv содержит оба пути
- **THEN** они применяются до запуска HTTPS с сохранением существующего приоритета окружения

### Requirement: Резервное получение через Vault AppRole
Если файловая пара не настроена либо хотя бы один файл отсутствует, система MUST пробовать существующее получение сертификата через Vault AppRole. Система MUST сохранять существующие имена переменных подключения, механизм AppRole и поля секрета `portal_chain` и `portal_key`.

#### Scenario: Файлы не настроены
- **WHEN** пути не заданы или заданы неполностью
- **THEN** система пробует существующий Vault-способ

#### Scenario: Deployment не подготовил один из файлов
- **WHEN** хотя бы один файл настроенной пары отсутствует
- **THEN** система пытается получить сертификат и ключ через Vault AppRole

#### Scenario: Резервный способ успешен
- **WHEN** Vault вернул корректные `portal_chain` и `portal_key`
- **THEN** backend использует их для HTTPS с прежним механизмом временных файлов и очистки

### Requirement: Ошибка найденной TLS-конфигурации
Найденная полная файловая пара, которая нечитаема, указывает на каталог либо содержит некорректные или несовместимые сертификат и ключ, MUST останавливать запуск. Система MUST NOT скрывать такую ошибку переключением на другой источник или HTTP.

#### Scenario: Найдены некорректные PEM-файлы
- **WHEN** оба файла найдены, но сертификат или ключ не загружаются как корректная TLS-пара
- **THEN** запуск завершается с ошибкой до начала обслуживания запросов

#### Scenario: Отсутствует доступ к найденной паре
- **WHEN** найденная конфигурация недоступна для чтения или содержит каталог вместо файла
- **THEN** backend завершается с ошибкой без резервного Vault-запроса

### Requirement: HTTP как третий вариант запуска
Поддерживаемая команда `python support_planner.py` MUST использовать HTTPS на `0.0.0.0:5093` при рабочей TLS-паре. Если смонтированная пара отсутствует и резервный Vault-способ не дал рабочую пару, система MUST запускаться по HTTP на том же адресе и порту с сообщением о выбранном протоколе.

#### Scenario: Оба источника недоступны
- **WHEN** файловая пара отсутствует и получение сертификата через Vault AppRole завершилось ошибкой
- **THEN** backend запускается по HTTP на 5093 и сообщает об этом без раскрытия секретов

#### Scenario: Резервный способ вернул некорректную пару
- **WHEN** смонтированная пара отсутствует и полученные из Vault сертификат и ключ не образуют рабочую PEM-пару
- **THEN** backend запускается по HTTP

#### Scenario: Локальный запуск без сертификатов
- **WHEN** пути сертификата и ключа не заданы и резервный Vault недоступен
- **THEN** команда запуска сохраняет обслуживание локального приложения по HTTP без обязательного сертификата

#### Scenario: Сертификат успешно получен
- **WHEN** выбранный источник дал корректную PEM-пару
- **THEN** HTTPS-клиент получает ответ backend, а обычный HTTP-запрос к этому порту не обслуживается как HTTP-приложение

### Requirement: Ошибки TLS не раскрывают секреты
Диагностика выбора источника и отказа запуска MUST указывать понятную причину без вывода PEM-содержимого, приватного ключа, Vault-токена, AppRole-секретов и тела ответа Vault. Полученные резервным способом временные файлы MUST сохранять очистку при завершении процесса.

#### Scenario: Vault вернул ошибку с чувствительными данными
- **WHEN** резервный запрос завершился ошибкой или некорректным ответом
- **THEN** итоговая диагностика не содержит тело ответа и значения секретов

### Requirement: Документация источников и совместимость локального запуска
Документация MUST описывать порядок «файлы Deployment → Vault AppRole → HTTP» и необходимость перезапуска при обновлении сертификатов. Система MUST сохранять возможность локального HTTP-запуска для существующих dev-прокси и production UI-сценариев при недоступности обоих источников сертификата.

#### Scenario: Локальная разработка
- **WHEN** backend запущен без смонтированной пары и доступного резервного Vault
- **THEN** существующие dev-прокси и UI-сценарии продолжают обращаться к нему по HTTP

#### Scenario: Ротация сертификата
- **WHEN** оператор обновляет смонтированные сертификат и ключ
- **THEN** документация указывает перезапуск backend для применения новой пары
