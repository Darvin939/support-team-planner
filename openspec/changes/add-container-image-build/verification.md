# Проверка реализации

## Выполнено

Добавлены `Dockerfile` и `.dockerignore`, два файла включены в allowlist `build-distribution.sh`. README описывает подготовку ZIP, добавление пользовательского `pip.conf`, Docker-сборку и запуск с отдельными PostgreSQL-миграциями. CI-job 2, Kubernetes-манифесты и пользовательский `pip.conf` не создавались. Backend, frontend-исходники и зависимости приложения не менялись.

По исходникам проверены согласованный базовый образ, COPY-пути, конфигурация pip, проверки frontend, Python-окружение, UID `1001:0`, права каталогов, порт `5093` и exec-CMD. `ENTRYPOINT []` явно сбрасывает возможную точку входа базового образа. Правила `.dockerignore` проверены статически; выполнение их Docker-builder здесь не подтверждено.

## Дистрибутив

Окружение: Python 3.9.25 из `.venv`, Node 20.19.5 и npm 10.8.2 с уже установленными frontend-зависимостями. Обе свежие production-сборки frontend прошли. Переустановка зависимостей через `npm ci` в этом прогоне не выполнялась; README рекомендует Node 24 для полного набора frontend-зависимостей.

Проверка запущена командой:

```sh
PYTHONUTF8=1 PYTHONIOENCODING=utf-8 python3 .tmp/verify_container_distribution.py
```

Успешны два сценария:

1. Реальное рабочее дерево без `pip.conf`, с `--output build/container-image-95b707e96f`.
2. Изолированная копия исходников с выходным путём по умолчанию и временными фикстурами: `pip.conf`, `.env`, SQLite/WAL/SHM, логи, backup/dump, тесты, кэши и OpenSpec.

В каждом ZIP **96 файлов**. Архив распакован; содержимое всех файлов побайтно совпало с выходным каталогом. Dockerfile и `.dockerignore` совпали с файлами проекта. Найдены готовые `index.html` и `taskTransitions.json`, backend, PostgreSQL SQL-миграция, CLI, версия и метаданные. Все 13 исключаемых фикстур отсутствуют в архиве; сборка не изменила их содержимое. После проверки фикстуры удалены из временной копии.

Из распакованного архива под Python 3.9 с отключённым dotenv успешно выполнены:

- `python -m scripts.migrate_database --help`;
- `python -m scripts.import_sqlite_to_postgres --help`;
- загрузка `VALID_TASK_TRANSITIONS`;
- чтение метаданных и сравнение с `app_build_metadata.json`: версия `0.1.5`, ID `148f250c-dirty`.

Рабочая `database.db` отсутствовала и не создавалась. Приложение, сервер PostgreSQL и контейнеры не запускались; проверочные Python-процессы завершились. UI-код не менялся, отдельный UI-прогон не выполнялся.

Артефакты: `build/container-image-95b707e96f.zip`, `.tmp/container-image-95b707e96f/result.json`, логи сборок и CLI в том же временном каталоге. Также успешны `bash -n build-distribution.sh`, `git diff --check` и `openspec validate add-container-image-build --strict`.

## Незавершённая приёмка

Команда `docker version` завершилась ошибкой `command not found: docker`. Podman и buildctl также не обнаружены. Поэтому корпоративный базовый образ не скачивался, установка зависимостей внутри него, фактическая фильтрация Docker-контекста, сборка образа и негативные Docker-сценарии отсутствующих входных файлов не проверены.

Запуск UID 1001, ротация логов, временные TLS-файлы, Python 3.12 и штатная остановка процесса внутри контейнера остаются непроверенными. `SUPPORT_PLANNER_TEST_DATABASE_URL` не задан; PostgreSQL runtime/pre-deploy и реальный вход в приложение из образа не проверялись. Пользовательский `pip.conf` из другого проекта не читался и не копировался.

Задачи 3.1–3.3 остаются открытыми. Сборка ZIP и локальные импорты не заменяют проверку контейнера. Публикация, настройка второй job и Kubernetes-развёртывание не выполнялись. Изменение не синхронизировано и не архивировано; commit не создан.
