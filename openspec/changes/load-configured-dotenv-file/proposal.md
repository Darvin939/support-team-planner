# Proposal

## Why

Vault Agent Injector формирует dotenv-файл `/config/secret/planner-env/env` со строками `KEY=value`. Приложение уже использует python-dotenv, поэтому ему нужен настраиваемый путь в существующем загрузчике конфигурации.

## What Changes

- Settings принимает один путь `SUPPORT_PLANNER_ENV_FILE` из окружения процесса и загружает этот UTF-8 dotenv-файл до импорта хранилища и прикладных модулей.
- Настоящее окружение имеет приоритет. В явно выбранном файле отключается подстановка `${...}`, чтобы сохранить значения секретов буквально.
- Ошибка чтения выбранного файла останавливает запуск; без переменной сохраняется поиск `.env`, а `SUPPORT_PLANNER_SKIP_DOTENV=1` отключает оба режима.
- Повторная загрузка `.env` в TLS-модуле удаляется.
- Удаляются добавленный shell-entrypoint, его тесты и изменения упаковки; Dockerfile возвращается к прямому запуску Python.
- README, POSTGRESQL.md и `.env.example` описывают dotenv от Vault KV v1 и его путь в Deployment.

## Capabilities

### New Capabilities

- `application-environment-configuration`: единая загрузка настроек из стандартного или явно выбранного dotenv-файла с приоритетом окружения и обработкой ошибок.

### Modified Capabilities

Нет. Требования к формату дистрибутива и контейнерному запуску сохраняются.

## Impact

Затрагиваются `backend/settings.py`, `backend/ssl_context.py`, документация и тесты настроек. API, схема БД, frontend и зависимости сохраняются. Python 3.9 поддерживается. Путь используется приложением и существующими CLI миграции и переноса. Секреты подключаются при запуске и не упаковываются в образ.
