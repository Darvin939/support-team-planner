## Purpose

Определяет единую загрузку настроек приложения и служебных команд из окружения и dotenv-файла до использования прикладных модулей.

## ADDED Requirements

### Requirement: Явный выбор dotenv-файла
Система MUST принимать `SUPPORT_PLANNER_ENV_FILE` из окружения процесса как один путь к UTF-8 dotenv-файлу и загружать его до выбора хранилища и прикладных настроек. Файл MUST обрабатываться как dotenv без исполнения shell. Путь с пробелами MUST поддерживаться.

#### Scenario: Файл от Vault Agent
- **WHEN** путь задан как `/config/secret/planner-env/env`, а файл содержит `KEY=value` с настройками PostgreSQL, схемы и сессии
- **THEN** приложение и CLI получают значения до инициализации прикладных модулей

#### Scenario: Путь с пробелами
- **WHEN** задан один существующий путь с пробелами
- **THEN** путь не разделяется и файл загружается

### Requirement: Приоритет и точность значений
Окружение процесса MUST иметь приоритет над файлом, включая пустые строки. Для явно выбранного файла система MUST сохранять `${...}` и shell-подобные выражения буквально и MUST NOT дополнять настройки из автоматически найденного `.env`.

#### Scenario: Значение задано в окружении и файле
- **WHEN** переменная присутствует в обоих источниках
- **THEN** сохраняется значение окружения

#### Scenario: Секрет содержит специальные символы
- **WHEN** корректно экранированное dotenv-значение содержит кавычки, обратную косую черту, `${...}`, `$()` или перевод строки
- **THEN** загружается исходное значение без подстановки переменных и исполнения команд

#### Scenario: Рядом существует локальный dotenv
- **WHEN** явно выбранный файл не содержит переменной из локального `.env`
- **THEN** локальный `.env` не добавляет переменную, включая последующий импорт TLS-модуля

### Requirement: Ошибки явно выбранного файла
При пустом пути, ошибке чтения, каталоге вместо файла или некорректном UTF-8 система MUST завершить загрузку с понятной ошибкой `SUPPORT_PLANNER_ENV_FILE` до выбора хранилища. Система MUST NOT скрывать ошибку переходом к другому файлу или печатать содержимое секретов.

#### Scenario: Файл не подготовлен
- **WHEN** явно указанный файл отсутствует или нечитаем
- **THEN** приложение не начинает работу с SQLite по умолчанию

#### Scenario: Некорректный путь или кодировка
- **WHEN** путь пуст, указывает на каталог или файл не декодируется как UTF-8
- **THEN** загрузка завершается с ошибкой без содержимого файла

### Requirement: Совместимый стандартный и тестовый запуск
Без `SUPPORT_PLANNER_ENV_FILE` система MUST сохранять существующий поиск `.env`, его интерполяцию и приоритет окружения. `SUPPORT_PLANNER_SKIP_DOTENV=1` MUST отключать загрузку обоих видов dotenv-файла.

#### Scenario: Локальная разработка
- **WHEN** явный путь отсутствует и стандартный `.env` доступен
- **THEN** настройки загружаются существующим способом

#### Scenario: Изолированный тестовый процесс
- **WHEN** dotenv отключён через `SUPPORT_PLANNER_SKIP_DOTENV=1`, даже при заданном недоступном файле
- **THEN** процесс использует своё окружение без чтения dotenv

### Requirement: Документированная интеграция Vault KV v1
Документация MUST описывать файл `env` в `/config/secret/planner-env`, KV v1 поля `.Data`, dotenv-значения и `SUPPORT_PLANNER_ENV_FILE` в окружении Deployment. Пример MUST включать URL PostgreSQL, схему, session secret, отдельный `PGPASSWORD` и перезапуск после обновления файла.

#### Scenario: Запуск по примеру Deployment
- **WHEN** Vault Agent подготовил файл и оператор задал его путь в окружении контейнера
- **THEN** штатный запуск Python загружает настройки без shell-wrapper и изменения команды приложения
