# Поддержка PostgreSQL 15 с сохранением SQLite

## Why

Развёртывание приложения должно поддерживать предоставляемый инфраструктурой PostgreSQL 15, сохраняя рабочий вариант SQLite и существующие данные. На переходный период два экземпляра работают параллельно: SQLite остаётся рабочим источником, PostgreSQL используется для тестирования на переносимых снимках. Сейчас выбран только SQLite: его диалект, модель транзакций и служебные API используются в DAO, миграциях и тестовых инструментах.

## What Changes

- Добавляется выбор PostgreSQL через `SUPPORT_PLANNER_DATABASE_URL`; без URL сохраняется SQLite и `SUPPORT_PLANNER_DB_PATH`. Ошибка PostgreSQL не включает SQLite автоматически.
- Существующий `DBBackend` получает PostgreSQL-адаптер на Psycopg 3.2 и явные операции для различий диалектов. Сохраняются Python 3.9, HTTP-контракты и публичные функции DAO.
- PostgreSQL получает baseline полной прикладной схемы, отдельные проверяемые миграции и проверку версии при startup. Миграции применяются отдельной pre-deploy командой; SQLite сохраняет автоматическое обновление.
- Форматы данных остаются совместимыми: текстовые даты и время, флаги 0/1, прежние ID, ограничения и правила удаления. Записи PostgreSQL сериализуются общей транзакционной блокировкой до проверок изменяемых данных.
- Сохраняются Unicode- и нечёткий поиск: SQLite использует общие Python-функции как UDF, PostgreSQL применяет их к ограниченным доступом кандидатам до SQL-пагинации.
- Добавляется перенос всей SQLite БД через новый согласованный backup при каждом запуске. Обычный импорт принимает пустое назначение; явный `--replace-target` полностью заменяет прикладные данные подготовленного PostgreSQL, включая все результаты тестирования. Очистка, загрузка, сверка и восстановление последовательностей ID выполняются атомарно.
- До финального переключения PostgreSQL остаётся тестовым, его изменения не возвращаются в SQLite. Повторные тестовые переносы не требуют остановки рабочего SQLite; окончательный перенос выполняется после остановки записи в SQLite и тестовом PostgreSQL. Граница отката — перевод рабочей эксплуатации на PostgreSQL.
- Общие проверки выполняются на обеих СУБД; обновляются demo-генераторы, UI-инструменты, дистрибутив и инструкции эксплуатации.

## Capabilities

### New Capabilities

- `postgresql-storage`: конфигурация и полноценное хранение в PostgreSQL 15 при сохранении SQLite, типов и поведения приложения, включая независимые параллельные экземпляры.
- `sqlite-postgresql-transfer`: проверяемый полный и повторный перенос SQLite с явной заменой тестовых данных PostgreSQL и финальным переключением в окно обслуживания.

### Modified Capabilities

- `db-connection-lifecycle`: единое request-scoped соединение выбранной СУБД и освобождение транзакции при любом исходе.
- `database-migration-integrity`: отдельные реестры двух СУБД и PostgreSQL pre-deploy без runtime DDL.
- `composite-write-atomicity`: атомарные операции на обеих СУБД и блокировка до проверок изменяемых данных.
- `task-fuzzy-search`: общий алгоритм с различным исполнением SQLite/PostgreSQL при одинаковой семантике.
- `codebase-maintainability`: используемый PostgreSQL backend вместо исторического ограничения на его отсутствие при декомпозиции.
- `application-distribution-build`: поставка обоих backend, миграций, переноса и инструкций без локальных данных и секретов.

## Impact

Затрагиваются `backend/db`, границы транзакций в роутерах, загрузка конфигурации, lifecycle приложения, зависимости, `scripts`, backend/UI-тесты, README, AGENTS и production-сборка. Новые зависимости включают `psycopg[binary]>=3.2,<3.3`; API и интерфейс пользователя не меняются.

Установка PostgreSQL, ORM, нативные DATE/TIMESTAMP/BOOLEAN, увеличение параллелизма записи, двусторонняя синхронизация, слияние тестовых изменений и обратный перенос после перевода рабочей эксплуатации на PostgreSQL не входят в изменение. Реальное переключение требует предоставленного назначения и окна обслуживания; реализация, sync, archive и commit выполняются после отдельных разрешений по AGENTS.md.
