## MODIFIED Requirements

### Requirement: Fuzzy task search clause is built consistently
Списки задач, их total, архив и выбор зависимостей SHALL использовать общее правило нечёткого поиска: каждое слово запроса совпадает с именем либо описанием по прежнему алгоритму допуска замен символов. SQLite и PostgreSQL SHALL давать одинаковые совпадения независимо от места выполнения алгоритма. Фильтрация SHALL предшествовать подсчёту и пагинации.

#### Scenario: Empty search
- **WHEN** search пустой или отсутствует
- **THEN** поиск не ограничивает строки, подходящие по остальным условиям

#### Scenario: Multi-word search
- **WHEN** search равен «биллинг ошибка»
- **THEN** остаются только задачи, в которых каждое слово отдельно нечётко совпадает с именем или описанием

#### Scenario: Same results across all three call sites
- **WHEN** список задач, его total и список выбора зависимостей используют одинаковый search и данные
- **THEN** они используют одинаковое правило совпадения, а список и total согласованы на неизменных данных

#### Scenario: Unicode и короткое слово
- **WHEN** поиск содержит кириллицу, Unicode-регистр или слово короче трёх символов
- **THEN** обе СУБД воспроизводят прежние правила нормализации, подстроки и допуска опечаток

#### Scenario: Совпадения находятся за первой страницей кандидатов
- **WHEN** подходящие задачи находятся за пределами первого пакета чтения
- **THEN** они учитываются в total и целевой странице без скрытого лимита кандидатов

#### Scenario: Принудительно включённые зависимости
- **WHEN** список зависимостей получает include_ids
- **THEN** допустимые задачи этих ID включаются по прежним правилам даже без совпадения search или вне основного лимита, без обхода доступа к команде
