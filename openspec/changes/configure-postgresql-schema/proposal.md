# Настраиваемая схема PostgreSQL

## Why

PostgreSQL backend, миграции и перенос из SQLite жёстко используют `public`. Развёртывание должно принимать имя заранее созданной администратором схемы через параметры экземпляра и по умолчанию работать с `planner`, сохраняя полный перенос SQLite → PostgreSQL.

## What Changes

- Добавляется `SUPPORT_PLANNER_DATABASE_SCHEMA` в окружении/`.env`; при отсутствии параметра используется `planner`. Переменная окружения имеет приоритет над `.env`.
- **BREAKING**: схема по умолчанию меняется с `public` на `planner`. Явное значение `public` остаётся допустимым. По уточнению пользователя данных в PostgreSQL `public` нет; перемещение таблиц между схемами не требуется.
- Администратор БД заранее создаёт выбранную схему и выдаёт права. Приложение, мигратор и импорт не создают её автоматически; отсутствие схемы или доступа приводит к понятной ошибке.
- Приложение, pre-deploy миграции, проверки структуры и импорт используют одну выбранную схему для всех прикладных таблиц, migration journal и последовательностей.
- Сохраняется перенос из SQLite: подготовка таблиц без bootstrap, обычный импорт, `--dry-run`, `--replace-target`, сверка и восстановление генерации ID работают в выбранной схеме.
- Обновляются примеры конфигурации, инструкция PostgreSQL и тестовые инструменты; параметр работает одинаково при локальном запуске и в контейнере.

## Capabilities

### New Capabilities

- `postgresql-schema-configuration`: выбор одной заранее созданной PostgreSQL-схемы для runtime, миграций и переноса SQLite с единым параметром и значением `planner` по умолчанию.

### Modified Capabilities

Нет. Спецификации общей поддержки PostgreSQL и переноса пока находятся в активном изменении `add-postgresql-backend`. Это изменение дополняет их отдельным контрактом выбора схемы и не меняет требования основного SQLite backend.

## Impact

Затрагиваются `backend/db/postgresql.py`, PostgreSQL migration runner, `scripts/migrate_database.py`, `scripts/import_sqlite_to_postgres.py`, PostgreSQL fixtures/integration-тесты, UI-harness, `.env.example`, `POSTGRESQL.md` и README. Содержимое опубликованного baseline и его checksum сохраняются. Новые зависимости не нужны, совместимость с Python 3.9 сохраняется.

Изменение опирается на существующую реализацию `add-postgresql-backend`. Создание инфраструктуры, фактический перенос пользовательской БД и финальное переключение эксплуатации выполняются отдельно; их готовность не следует из реализации параметра.
