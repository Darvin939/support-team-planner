# Контроль доступа к командам

## Purpose

Определяет эффективный доступ пользователей к командам, обязательную backend-авторизацию командных данных и допустимость исполнителей назначений.

## Requirements

### Requirement: Эффективный доступ пользователя к командам
Система SHALL считать администратора имеющим доступ ко всем командам; для редактора или пользователя непустой набор разрешённых команд SHALL ограничивать доступ этим набором, а отсутствие связей SHALL означать доступ ко всем командам.

#### Scenario: Ограниченный пользователь получает список команд
- **WHEN** редактор или пользователь имеет хотя бы одну явно разрешённую команду
- **THEN** `/api/teams` возвращает только разрешённые ему команды

#### Scenario: Ограничения не заданы
- **WHEN** у редактора или пользователя нет явно разрешённых команд
- **THEN** ему доступны все команды

#### Scenario: Администратор имеет полный доступ
- **WHEN** администратор обращается к командным данным
- **THEN** система разрешает доступ независимо от сохранённых для него связей

### Requirement: Backend защищает все командные данные
Система MUST проверять эффективный доступ на backend для чтения и изменения команды, её настроек, задач, зависимостей, назначений, статистики и журнала, включая endpoints, где команда определяется через идентификатор задачи или назначения.

#### Scenario: Прямой запрос недоступной команды
- **WHEN** пользователь передаёт `team_id` недоступной команды непосредственно в URL или теле запроса
- **THEN** backend отвечает `403` и не читает и не изменяет данные этой команды

#### Scenario: Косвенный запрос через задачу или назначение
- **WHEN** пользователь обращается к задаче или назначению, принадлежащему недоступной команде
- **THEN** backend определяет команду связанной сущности и отвечает `403`

#### Scenario: Агрегат по нескольким командам
- **WHEN** статистический запрос явно содержит хотя бы одну недоступную команду
- **THEN** backend отвечает `403`, не возвращая частичный результат

#### Scenario: Агрегат без явного списка команд
- **WHEN** ограниченный пользователь запрашивает статистику без конкретных команд
- **THEN** backend агрегирует только доступные ему команды

### Requirement: Исполнитель доступен только в разрешённой ему команде
Система SHALL показывать и принимать в назначении только пользователей, чей эффективный доступ включает команду соответствующей задачи.

#### Scenario: Формирование выбора исполнителя
- **WHEN** открывается выбор исполнителя для задачи конкретной команды
- **THEN** список содержит администраторов, пользователей без ограничений и пользователей с явным доступом к этой команде

#### Scenario: Прямая попытка назначить недоступного пользователя
- **WHEN** клиент передаёт `user_id` пользователя, которому недоступна команда задачи
- **THEN** backend отклоняет создание или изменение назначения с ошибкой `400`

### Requirement: Новая команда не теряется для ограниченного редактора
Система SHALL сохранять доступ ограниченного редактора к созданной им команде.

#### Scenario: Ограниченный редактор создаёт команду
- **WHEN** редактор с непустым набором разрешённых команд создаёт новую команду
- **THEN** backend добавляет новую команду в его разрешённый набор
