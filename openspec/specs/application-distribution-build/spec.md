# Application Distribution Build

## Purpose

Определяет формирование переносимого Linux-дистрибутива приложения из Python runtime-файлов и актуальных production frontend-артефактов.

## Requirements

### Requirement: Сборка актуального дистрибутива
Система MUST предоставлять исполняемый Linux shell-скрипт, который перед формированием дистрибутива успешно выполняет production-сборку frontend и прекращает работу с ошибкой, если frontend не собран.

#### Scenario: Успешная production-сборка
- **WHEN** оператор запускает shell-скрипт в Linux из корректного рабочего дерева с установленными frontend-зависимостями
- **THEN** скрипт выполняет production-сборку frontend и формирует выходной каталог из полученных артефактов

#### Scenario: Ошибка frontend-сборки
- **WHEN** команда production-сборки frontend завершается с ненулевым кодом
- **THEN** скрипт завершается с ошибкой и не публикует частично сформированный выходной каталог

### Requirement: Полный минимальный состав
Скрипт MUST включать в дистрибутив Python runtime-исходники приложения, `requirements.txt`, production launch-скрипты, `frontend/dist` и runtime-файл frontend-данных, сохраняя относительные пути, ожидаемые приложением.

#### Scenario: Проверка состава результата
- **WHEN** сборка дистрибутива завершена успешно
- **THEN** приложение может импортироваться и находить production frontend и файл переходов статусов из выходного каталога

### Requirement: Исключение локальных и development-данных
Скрипт MUST формировать дистрибутив по явному списку runtime-файлов и MUST NOT включать локальную SQLite БД, WAL/SHM-файлы, `.env`, логи, кэши, virtualenv, `node_modules`, frontend-исходники за исключением обязательного runtime-файла, тесты и OpenSpec-артефакты.

#### Scenario: Локальные файлы присутствуют в рабочем дереве
- **WHEN** в репозитории существуют БД, секреты, кэши или другие исключённые development-файлы
- **THEN** они отсутствуют в готовом дистрибутиве

### Requirement: Управляемый и безопасный выходной каталог
Скрипт MUST поддерживать параметр `--output` для настраиваемого выходного каталога, использовать отдельный каталог по умолчанию и MUST защищать корень репозитория от использования в качестве цели замены.

#### Scenario: Выходной каталог по умолчанию
- **WHEN** оператор запускает скрипт без параметра выходного пути
- **THEN** дистрибутив создаётся в документированном каталоге `build/support-team-planner`

#### Scenario: Указан корень репозитория
- **WHEN** оператор указывает корень репозитория как выходной каталог
- **THEN** скрипт завершается с ошибкой до удаления или перезаписи файлов проекта

### Requirement: Документированный запуск
Документация MUST описывать команду создания дистрибутива, его состав, необходимость установки Python-зависимостей и команду запуска из выходного каталога.

#### Scenario: Подготовка установки по документации
- **WHEN** оператор следует README на машине с Python
- **THEN** он может установить зависимости и запустить приложение из сформированного каталога
