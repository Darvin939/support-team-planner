# Каталог пользователей в настройках

## Purpose

Определяет отображение, поиск и пагинацию учётных записей на вкладке пользователей, а также совместимость API со сценариями, которым нужен полный список.

## Requirements

### Requirement: Пользователи отображаются в таблице
Система SHALL отображать список учётных записей на вкладке пользователей в Ant Design `Table` с колонками «ФИО», «Роль», «Логин», «Команды» и «Действия». Колонка «Команды» SHALL показывать до трёх названий явно выбранных команд, обозначать количество остальных команд и предоставлять полный список во всплывающей подсказке; отсутствие явно выбранных команд SHALL отображаться как «Все команды».

#### Scenario: Администратор открывает список
- **WHEN** администратор открывает вкладку пользователей
- **THEN** каждая строка показывает полное ФИО, локализованную роль, логин, компактное представление доступных команд и кнопки доступных действий

#### Scenario: Неадминистратор открывает список
- **WHEN** редактор или обычный пользователь открывает доступный ему список
- **THEN** таблица показывает компактное представление доступных команд и не показывает кнопки изменения и удаления

#### Scenario: У пользователя не больше трёх выбранных команд
- **WHEN** строка пользователя содержит от одной до трёх явно выбранных команд
- **THEN** колонка «Команды» показывает названия всех этих команд

#### Scenario: У пользователя больше трёх выбранных команд
- **WHEN** строка пользователя содержит больше трёх явно выбранных команд
- **THEN** колонка «Команды» показывает первые три названия, количество скрытых команд в виде `+N` и полный список названий во всплывающей подсказке

#### Scenario: Пользователь не имеет явных ограничений
- **WHEN** `team_ids` пользователя пуст
- **THEN** колонка «Команды» показывает «Все команды»

### Requirement: Список имеет серверную пагинацию
Система SHALL применять `offset` и `limit` до возврата данных и SHALL возвращать общее число строк, соответствующих текущему поиску.

#### Scenario: Переход на другую страницу
- **WHEN** пользователь меняет страницу в `Pagination`
- **THEN** frontend запрашивает соответствующий `offset`, а backend возвращает только данные этой страницы

#### Scenario: Изменение размера страницы
- **WHEN** пользователь выбирает 10, 20, 50 или 100 строк
- **THEN** frontend сбрасывает список на первую страницу и запрашивает выбранный `limit`

### Requirement: Поиск охватывает всех пользователей
Система SHALL фильтровать пользователей на backend до пагинации по подстроке в логине, полном ФИО или роли.

#### Scenario: Поиск по логину или ФИО
- **WHEN** пользователь вводит подстроку логина или любой части ФИО
- **THEN** таблица показывает все совпадения независимо от их исходной страницы

#### Scenario: Поиск по роли
- **WHEN** пользователь вводит техническое или русское название роли
- **THEN** таблица показывает учётные записи соответствующей роли

### Requirement: Полный список остаётся совместимым
Система SHALL сохранять формат полного массива для `GET /api/users` без параметров пагинации и поиска.

#### Scenario: Форма запрашивает полный список
- **WHEN** frontend вызывает `/api/users` без `offset`, `limit` и `search`
- **THEN** backend возвращает прежний массив всех пользователей

### Requirement: Администратор задаёт доступные команды пользователя
Система SHALL позволять администратору выбрать разрешённые команды при создании и редактировании пользователя; пустой выбор SHALL означать доступ ко всем командам.

#### Scenario: Создание ограниченного пользователя
- **WHEN** администратор создаёт пользователя и выбирает одну или несколько команд
- **THEN** система сохраняет выбранные команды как его явный набор доступа

#### Scenario: Сохранение пустого выбора
- **WHEN** администратор сохраняет пользователя без выбранных команд
- **THEN** система удаляет его явные ограничения и предоставляет доступ ко всем командам

#### Scenario: Редактирование пользователя
- **WHEN** администратор открывает существующего пользователя
- **THEN** форма показывает сохранённые разрешённые команды и поясняет, что пустой список означает все команды

#### Scenario: Защищённый администратор
- **WHEN** администратор редактирует защищённую учётную запись администратора по умолчанию
- **THEN** управление разрешёнными командами недоступно, поскольку администратор всегда имеет полный доступ
