# Статусы назначений

## Purpose

Определяет допустимые статусы назначений и их отображение в интерфейсе.

## Requirements

### Requirement: Назначение можно отменить отдельным статусом
Система SHALL поддерживать для назначения статус `cancelled` и показывать его пользователю как «Отменено».

#### Scenario: Выбор отмены в форме
- **WHEN** редактор открывает список статусов в форме назначения
- **THEN** в списке доступен вариант «Отменено» со значением `cancelled`

#### Scenario: Быстрая смена статуса
- **WHEN** редактор открывает контекстное меню назначения с другим статусом
- **THEN** в группе статусов доступено действие «Отменено»

#### Scenario: Отображение отменённого назначения
- **WHEN** API возвращает назначение со статусом `cancelled`
- **THEN** таблица планирования и история изменений показывают метку «Отменено»

#### Scenario: Отмена не считается активным назначением
- **WHEN** назначение имеет статус `cancelled`
- **THEN** оно не входит в выборку и счётчики активных назначений

### Requirement: Назначение может завершиться неуспешно
Система SHALL поддерживать самостоятельный статус назначения `unsuccessful`, показывать его пользователю как «Неуспешно» и визуально обозначать красным цветом и иконкой ошибки там, где статусы представлены действиями с иконками.

#### Scenario: Выбор неуспешного статуса
- **WHEN** редактор или администратор открывает список допустимых статусов назначения
- **THEN** система предлагает вариант «Неуспешно» со значением `unsuccessful`

#### Scenario: Сохранение неуспешного назначения через API
- **WHEN** авторизованный редактор или администратор сохраняет назначение со статусом `unsuccessful`
- **THEN** API принимает значение и возвращает назначение с сохранённым статусом `unsuccessful`

#### Scenario: Отображение неуспешного назначения
- **WHEN** интерфейс получает назначение со статусом `unsuccessful`
- **THEN** календарная сетка, история или таймлайн, фильтры и статистика используют подпись «Неуспешно» и красное визуальное обозначение

#### Scenario: Неуспешное назначение не является активным
- **WHEN** неудалённое назначение имеет статус `unsuccessful`
- **THEN** оно не входит в выборки и признаки активных назначений и не блокирует действия, зависящие от отсутствия активных назначений

#### Scenario: Неизвестный статус остаётся недопустимым
- **WHEN** клиент передаёт статус назначения вне полного поддерживаемого перечня, включающего `unsuccessful`
- **THEN** backend отклоняет запрос ошибкой валидации до записи данных
