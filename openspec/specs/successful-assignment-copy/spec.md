# Копирование успешных назначений

## Purpose

Определяет получение полной истории успешных назначений отдельной работы, выбор актуальной даты каждого блока и копирование результата в согласованном текстовом формате.

## Requirements

### Requirement: Полная история успешных назначений работы
Система SHALL по явному запросу авторизованного пользователя возвращать всю неудалённую историю назначений со статусом `success` для указанной работы без ограничения выбранным в интерфейсе диапазоном дат. Система MUST проверять доступ пользователя к команде и принадлежность работы этой команде.

#### Scenario: История не ограничивается экранным диапазоном
- **WHEN** пользователь запускает копирование для доступной ему работы, у которой успешные назначения находятся внутри и вне выбранного диапазона планирования
- **THEN** система использует успешные назначения работы за всю историю

#### Scenario: Другие статусы и удалённые записи исключены
- **WHEN** история работы содержит неудалённые и soft-deleted назначения с различными статусами
- **THEN** система возвращает только неудалённые назначения со статусом `success`

#### Scenario: Доступ к чужой команде запрещён
- **WHEN** пользователь запрашивает историю работы команды, к которой у него нет доступа
- **THEN** система отклоняет запрос согласно действующей политике доступа к командам

### Requirement: Уникализация блоков по последней успешной дате
Система SHALL разделять составное значение назначения по запятым, удалять окружающие пробелы, игнорировать пустые элементы и оставлять для каждого уникального блока только его самое позднее успешное назначение.

#### Scenario: Повтор блока в разные даты
- **WHEN** один блок имеет несколько успешных назначений в разные даты
- **THEN** в итоговый текст входит только этот блок с самой поздней успешной датой

#### Scenario: Более новое назначение имеет другой статус
- **WHEN** после успешного назначения блока существует более новое назначение этого блока со статусом, отличным от `success`
- **THEN** в итоговый текст входит последнее успешное назначение блока

#### Scenario: Составное значение блоков
- **WHEN** успешное назначение содержит несколько названий блоков через запятую и окружающие пробелы
- **THEN** каждый непустой блок участвует в уникализации независимо

### Requirement: Формат текста назначений
Система SHALL формировать текст с названием работы в первой строке без квадратных скобок и последующими строками вида `Блок 1, Блок 2 - ДД.ММ.ГГГГ`. Система MUST группировать блоки с одинаковой итоговой датой в одну строку и сортировать строки дат по возрастанию.

#### Scenario: Несколько итоговых дат
- **WHEN** после уникализации остаются блоки на нескольких датах
- **THEN** первая строка содержит название работы, а следующие строки содержат сгруппированные блоки в хронологическом порядке и даты в формате `ДД.ММ.ГГГГ`

#### Scenario: Несколько блоков на одной дате
- **WHEN** последние успешные назначения нескольких уникальных блоков имеют одну дату
- **THEN** названия этих блоков перечислены через запятую в одной строке перед датой

### Requirement: Действие копирования в меню работы
Система SHALL показывать действие «Копировать назначения» в контекстном меню каждой видимой работы всем пользователям, имеющим доступ на просмотр, включая работы в терминальном статусе и пользователей без права редактирования.

#### Scenario: Пользователь без права редактирования
- **WHEN** пользователь с доступом на просмотр открывает контекстное меню работы
- **THEN** ему доступно действие «Копировать назначения»

#### Scenario: Завершённая работа
- **WHEN** пользователь открывает контекстное меню завершённой работы
- **THEN** ему доступно действие «Копировать назначения»

### Requirement: Результат операции копирования
Система SHALL записывать сформированный текст в буфер обмена браузера и показывать уведомление «Назначения скопированы». Если подходящих блоков нет, система MUST не изменять буфер и показать «Нет успешных назначений». При ошибке загрузки или записи в буфер система MUST показать «Не удалось скопировать назначения».

#### Scenario: Успешное копирование
- **WHEN** история содержит хотя бы один непустой блок успешного назначения и Clipboard API успешно записывает текст
- **THEN** система копирует сформированный текст и показывает «Назначения скопированы»

#### Scenario: Подходящих назначений нет
- **WHEN** история не содержит непустых блоков успешных назначений
- **THEN** система не вызывает запись в буфер и показывает «Нет успешных назначений»

#### Scenario: Ошибка операции
- **WHEN** запрос истории или запись в буфер завершается ошибкой
- **THEN** система показывает «Не удалось скопировать назначения» и не сообщает об успехе
